# Worker commands: operations and quality

Part of the [worker index](../workers.md): what each `cmd/<name>` worker does, when it runs, what it needs, and the trap behind it. Schema migration, probes, queue metrics, audits and read-only reports.

- `migrate` — run **before** deploying code that reads new schema. `-baseline` records on-disk files without executing; a pre-runner database auto-baselines on first run.
- `llm-probe` — asks **every model alias this deployment routes through** a trivial question three times each and publishes what came back as Prometheus gauges (`freehire_llm_probe_{attempts,ok,slowest_seconds}`, one series per alias, labelled `model`) via the node_exporter textfile collector. Every 5 minutes. Needs `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL`, reads `ASSISTANT_MODEL` and `SEARCH_INTENT_MODEL` beside them (each falling back to `LLM_MODEL`, as `cmd/server` does, and deduped so an unset one is not probed twice), and is a **no-op that spends nothing** without `PROM_TEXTFILE_DIR`. **Watching one alias was not enough**: measured 2026-09-09, `flagship` answers from z.ai and carries the assistant, the fit analysis and enrichment, while `fast` answers from Gemini and carries the AI search filter — a dead `fast` is a 500 on every AI search, and the old single-alias probe would have gone on reporting the gateway healthy. It exists because nothing measured what a provider ANSWERS: three times in the week to 2026-09-08 a provider behind the gateway stopped serving while the gateway reported it `active` — Cerebras on an empty wallet (402), then two Z.ai accounts, one under a Fair Usage Policy (429) and one with a revoked key (401) — and each was found by a person noticing a broken feature. It probes the ALIAS, not individual keys: only the gateway host holds the raw keys (the admin API returns them masked), so it cannot name which key is dead, only what share of requests are served at all. **A failing alias exits 0** — a red unit meaning "the thing I watch is broken" is indistinguishable from one meaning "I am broken". See [internal/platform/worker/AGENTS.md](../../../internal/platform/worker/AGENTS.md).
- `queue-metrics` — measures outbox depth, board-fleet health, catalogue freshness, and employment-type boilerplate (`freehire_employment_boilerplate`), and publishes them as Prometheus gauges via the node_exporter textfile collector. **Per-source data quality** (`freehire_source_quality_gap{source,check}` — open postings with no work mode, no geography, no company, unseen 7+ days, posted 60+ days ago) is published here too but MEASURED by `cmd/rollup-stats`, in the per-source scan it already runs every 3 hours: that scan reads the whole open catalogue and does not fit a one-minute worker, so this reads the `source_stats` snapshot and publishes its age beside it (`freehire_source_stats_measured_timestamp_seconds`) — a stopped rollup shows as an ageing snapshot, not as frozen counts. Needs `DATABASE_URL`, and is a **no-op that never opens the pool** without `PROM_TEXTFILE_DIR`. Read-only and lock-free by design — run it every minute; see [internal/platform/worker/AGENTS.md](../../../internal/platform/worker/AGENTS.md) for the published names.
- `quality-audit` — weekly, MEASURE ONLY: checks a sample of the catalogue against the world, the layer above `source-quality-metrics` (which counts what is missing; this counts what is wrong). **Liveness**: for every source with `source_stats.open_jobs >= 500` it probes ~30 random open postings' stored URLs and counts how many the source answers gone (404/410) or live (2xx on the posting's own URL) — reading the STATUS only, because the shared body classifier read arbeitnow's live pages as closed. AppOne uses its authoritative same-host posting JSON API (and requires a nonempty description), since its live Angular page can return 404. A verdict counts only on a source on a host that first 404'd a canary (the URL with its posting id rewritten to one that cannot exist), so a source answering 200 for any id (jobtech) or walled off (adzuna, wellfound) reads as unmeasured, never 0% dead; hh/djinni/torre keep CLOSED postings at 200 and are declared unmeasurable outright (`statusBlind`). robots.txt and Crawl-delay are honoured, one request at a time per host spaced 2s, a 403/429 ends the host, and `QUALITY_AUDIT_MAX_REQUESTS` (default 15000) bounds the run. **Remote**: ~200 postings tagged `remote` a week (`QUALITY_AUDIT_REMOTE_MAX`, `_PER_SOURCE` default 20; half the budget reserved for global-tagged postings, the other half for non-global remote postings; sources drawn weighted within each stratum) are read by an LLM judge on the SERVICE credential (`feature: quality-audit`) that must quote the posting or answer `unclear`; grounded quotes for contradictions appear in the run log; judgements land in `remote_audit_judgements` and the gauges cover 56 days. Publishes `freehire_audit_{liveness,remote,global}_*{source}` and `freehire_audit_measured_timestamp_seconds{check}` to `freehire-quality-audit.prom` — raw counts, plus `freehire_audit_liveness_unmeasured{source,reason}` coverage failures; the alert owns thresholds, and `live + dead = 0` means unmeasurable. Stratified remote counts describe the judged sample, not catalogue-wide error prevalence. Liveness sampling first materializes candidate IDs from the open `(source,id)` index before loading posting rows. Never closes or retags anything. A **no-op that never opens the pool** without `PROM_TEXTFILE_DIR`; `-dry-run` runs both passes, stores nothing and prints the exposition. Needs `DATABASE_URL` and `LLM_*` (without them the remote pass is skipped). See [internal/job/qualityaudit](../../../internal/job/qualityaudit/evidence.go) and `openspec/changes/add-sampled-quality-audit/design.md`.
- `report-cv-letters` — hand-run, read-only: per CV lifecycle letter, sent, delivered, clicked (SES) and how many recipients started paying within 14 days, against the holdout that was never mailed, on the letter's own clock. Needs only `DATABASE_URL`; run it with `go run`. Reading rules, and why opens are n/a, in [internal/engage/cvlifecycle/AGENTS.md](../../../internal/engage/cvlifecycle/AGENTS.md#reports).
- `report-skill-gaps` / `report-classify-drift` — hand-run, read-only reports (`internal/job/dictgap`) that mine LLM enrichment output nothing else reads: `enrichment.skills` is a free-text list the model writes per posting, and `enrichment.seniority`/`category` is the model's own guess at the same facets `internal/dict/classify` derives independently from the title. `report-skill-gaps` ranks the raw skill phrases `internal/dict/skilltag` resolves to no canonical, by frequency; `report-classify-drift` recomputes `classify.Parse` for every distinct enriched title and ranks the titles where that answer disagrees with what enrichment recorded, tracked separately for seniority and category. Neither writes anything — no database row, no dictionary source file, no `--apply` flag — and neither is on a timer: a curator runs one, reads the ranked list, and decides by hand what belongs in `dictionaries.go`/`labels.go`/`descriptions.tsv` or the `classify` title tables. No reindex needed either, since nothing they touch changes. Needs only `DATABASE_URL`. **`report-geo-gaps`** is the third of them, for `internal/dict/location`: it re-runs `location.Parse` on every distinct location string among publishable postings and compares it with `enrichment.countries`, printing GAPS (the dictionary places the location nowhere — no country and no region — while the model names a country) and CONFLICTS (the dictionary names countries most of the location's postings contradict, the `georgia` shape). Its share column is the confidence signal: the model is also asked about `Remote`-only postings and answers those with a guess, so a 40% share is noise and a 97% one is a missing name.
- `catalog-coverage` — hand-run, read-only: how much of an outside catalogue ours holds. Takes a sampled CSV (`name,title,url[,ref]`) and buckets each row: `have` (same role at the same folded company by `jobhash.RoleKey`, or, on an ATS board we crawl, a posting whose native id the link carries or whose title is the same role), `known_board` (its ATS board is ours, the posting is not: a crawl gap), `new_board` (a board we recognise but do not crawl: feed the same CSV to `seed-from-inventory`, then `harvest-boards`), `known_company` / `unknown_company`. Writes a per-row report and prints the share held per `ref`. The trap: a title with a parenthesised suffix (`Engineer (Remote)`) keeps its words under `RoleKey`, so it misses the plain title, and an employer named differently by the other catalogue misses the company key — `known_company` is an upper bound on the gap, not the gap. Keep its own queries index-backed: an ad-hoc check by company name scans `jobs`.
