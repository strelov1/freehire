## Why

A prior attempt to default the main jobs search to a hybrid (keyword+semantic) blend was rejected after code review: `jobs_semantic` is gated on `is_tech=TRUE` at the embed-enqueue level, so it silently excludes real, not-yet-classified jobs from any query that touches it — a materially different, smaller document set than the keyword `jobs` index. Investigating alternatives surfaced that the *only* legitimate remaining consumers of semantic similarity are `/jobs/:slug/similar` and CV-based `/recommendations`, and that `/similar` doesn't need a live index at all: "which jobs are similar to job X" is answerable once per job and cached, exactly like the sibling project `../telagon` already does for "similar channels" (`cmd/similar-backfill` + a precomputed lookup table). `jobs.semantic_embedding` (Postgres) is already the source of truth for job vectors and already has *more* coverage (1,610,951 rows) than the live `jobs_semantic` Meili index (1,021,471 docs, since it inherited the is_tech gate and Postgres never did).

Given that, keeping a second, expensive-to-rebuild, drifting Meili index alive is no longer justified. A local (non-prod) spike this session confirmed `pgvector` is installable on prod's self-managed Postgres 18 and answers nearest-neighbor queries correctly and fast — both for the batch precompute path `/similar` needs and the live per-request path `/recommendations` still genuinely needs (its query vector is a specific user's CV, combined with arbitrary facet filters chosen at request time — not precomputable the same way).

Mid-implementation, three more decisions were folded in rather than deferred (see design.md for full rationale): (1) an unmerged sibling branch had already diagnosed that today's embedding passage is HTML-laden and doubly-truncated, so only ~15-20% of an average description is ever embedded — since this change already redesigns where and how vectors are stored, its full-description/HTML-stripped/chunked fix is adopted now rather than shipped later against a schema that would need redoing; (2) `/similar` excludes same-company matches, so a "similar jobs" list isn't dominated by one employer's near-duplicate postings; (3) `/me/recommendations` (CV-based job ranking) and its "Recommended" feed sort are **removed entirely, not migrated** — investigating the pgvector migration for this endpoint (arbitrary per-request facet filters combined with a live vector rank, needing either a new SQL facet translator or a capped two-stage Meili-then-pgvector lookup) surfaced enough real complexity, for a feature of uncertain usage, that the user chose to drop it rather than carry that complexity forward.

## What Changes

- **New**: job descriptions are embedded as HTML-stripped, full-length text split into chunks (a job with a long description gets multiple embedding vectors, not one truncated one) — `job_semantic_chunks` (one row per chunk) replaces the single-vector-per-job storage originally planned. Fixes a real quality problem (only ~15-20% of an average description was ever embedded before) as part of this same migration rather than as a separate later change.
- **New**: `jobs.similar_job_ids`/`similar_computed_at`, populated by a new run-once-and-exit worker, `cmd/similar-backfill`, mirroring `../telagon/server/cmd/similar-backfill` — for every open job with embedding chunks but no (or stale) precomputed neighbours, runs a pgvector nearest-neighbour-over-chunks query (excluding same-company candidates) and writes the top-N job IDs. Idempotent, incremental, re-runnable on a cron.
- **Changed**: `GET /api/v1/jobs/:slug/similar` reads from `jobs.similar_job_ids` (a plain indexed lookup) instead of querying the live `jobs_semantic` Meili index, and never returns a job from the same company as the source. Same route, same response envelope, same public contract otherwise.
- **Removed** (**BREAKING**, public API and SPA): `GET /api/v1/me/recommendations` and the jobs feed's "Recommended" CV-similarity sort mode are dropped entirely — not migrated to pgvector. Per-request facet filters combined with a live vector rank need either a new SQL facet-filter translator (large, correctness-risky, duplicates already-trusted Meili filter logic) or a capped two-stage Meili-then-pgvector lookup (real complexity for a feature of uncertain usage); the user chose removal over carrying that complexity forward. Its CV-embedding write path (on résumé upload) is removed alongside it — nothing reads a CV embedding once this ships.
- **Removed** (**BREAKING** for internal ops tooling, not for any public API): the `jobs_semantic` Meili index and everything that builds or serves it —
  - `internal/search/client.go`: `semanticSettings`, `EnsureSemanticIndex`, `NewSemanticRebuild`, `IndexSemanticJobs`, `IndexSemanticJobsFromPG`, `ResetSemanticIndex`, `SimilarJobs` (Meili-backed), `RecommendByVector` (Meili-backed) — replaced by the pgvector-backed equivalents.
  - `cmd/reindex --semantic` (and its `--from-pg` / `--posted-within` flags) — the whole semantic swap-rebuild path.
  - The Meili-write half of `cmd/embed`'s `Indexer` port. The open-job path writes `job_semantic_chunks` and provenance stamps instead of a Meili document; the legacy `jobs.semantic_embedding` column is no longer written on the open path (only cleared on the closed path) and is dropped in a later change once nothing reads it.
  - `semantic_ratio` from the public search API (`internal/handler/search.go`, `GET /api/v1/jobs/search`) and every SPA caller of it (`web/src/lib/api.ts`) — the general keyword+facet search stays keyword-only, as it already effectively was.
  - `pgvector` extension gets installed on prod Postgres (new operational dependency, replacing Meili's embedder infrastructure for this purpose — TEI embedding itself is unaffected, only where the resulting vectors are queried).

## Capabilities

### New Capabilities

(none — this extends existing capabilities rather than introducing a new one)

### Modified Capabilities

- `similar-jobs`: "Similar-documents query over the semantic index" requirement changes from a live Meili similar-documents call to a precomputed-table lookup; adds the backfill worker's behavior as a new requirement.
- `semantic-embedding`: drops every Meili-index-write/delete requirement (`jobs_semantic` upsert/delete, the `reindex --semantic` reconciler) — the pipeline's only remaining effect is persisting/clearing `jobs.semantic_embedding` in Postgres.
- `cv-recommendations`: **all three requirements removed** — the endpoint, its feed sort mode, and the CV-embedding persistence they depended on are dropped, not migrated (see Why).
- `job-search`: removes the "Hybrid keyword and semantic search" requirement entirely (superseding the change that would have defaulted it on) — keyword search over the `jobs` index is unaffected.

## Impact

- **Code**: `internal/search` (client.go — large reduction, plus `chunkText`/`stripToPlainText` ported in from the sibling chunking branch), `internal/embed` (rewritten to chunk+embed+persist to `job_semantic_chunks` instead of writing Meili), `cmd/reindex` (drops `--semantic`/`--from-pg`/`--posted-within`), `internal/handler/search.go` + `similar.go`, `web/src/lib/api.ts`, a new `cmd/similar-backfill` + its `internal/similarjobs`-equivalent package, a new migration (pgvector extension + `job_semantic_chunks` table + `jobs.similar_job_ids`/`similar_computed_at`). Also removed outright: `internal/handler/recommendations.go`, its route, its résumé-upload CV-embedding write path, and the SPA's CV-sort UI (`JobsView.svelte`, `facetModel.ts`, `api.ts`'s `recommendations()`).
- **Data**: the existing `jobs.semantic_embedding` (`real[]`, single truncated vector per job) is superseded by `job_semantic_chunks` (multiple full-description chunk vectors per job) — not a cheap reshape, a genuine full-catalogue re-embed (bump `embedderModel`, let the existing staleness pipeline drain it). An HNSW index on `job_semantic_chunks.embedding` (built manually as a deferred prod operation) is what `cmd/similar-backfill`'s per-job nearest-neighbour query needs at scale — exact migration/index-build mechanics belong in design.md.
- **Ops**: `postgresql-18-pgvector` needs installing on prod; `freehire-reindexw`-adjacent cron/timers tied to `--semantic` go away; a new `cmd/similar-backfill` cron cadence needs adding, mirroring how `cmd/embed` is scheduled.
- **Docs**: `internal/search/AGENTS.md`, `internal/embed/AGENTS.md` need updates reflecting the removed Meili semantic index; a new module doc for the similar-jobs backfill (or folded into `internal/embed/AGENTS.md`) is warranted per this repo's per-package AGENTS.md convention.
