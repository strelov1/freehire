**Torre traps** (`torre`; live-verified 2026-10-15):

- **The search API is gone and the search moved behind robots.txt.** `POST search.torre.co/opportunities/_search` answers 400 `{"meta":{"message":"Invalid request"}}` to every body, `{}` included; torre.ai's job search redirects into `/app`, which robots.txt disallows (as it does `/api/` and `/search/jobs?*`). What robots.txt leaves open, and names, is the sitemap index and the `/post/<id>-<slug>` pages.
- **The sitemap index is the live catalogue, nearly.** 34 shards (`sitemap-en-N`, `sitemap-es-N`) named 2,440 distinct postings; shards are pruned as postings close (the 2023 shard still names one posting, whose `validThrough` lies ahead). Nearly is not exactly: 12-13 of 2,440 were closed (the page state reads `status="closed"`) and such a page carries NO JobPosting, so the posting is deferred and re-requested every run. Hence no `fullCatalog`. Two shards the index names (`sitemap--1.xml`, `sitemap--2.xml`) answer 404 and are skipped; any other shard failing fails the run, because a skipped shard reads as its postings closing.
- **The external id is the 8-character id before the slug.** Four entries carry no slug at all, and one id appeared in two shards.
- **The JobPosting description is escaped twice.** Once JSON-decoded it still holds `\uXXXX` for every non-ASCII character, `\/` and `\t` (37 of 61 sampled), so it is decoded again as a JSON string. Postings Torre crawled from elsewhere (identifier `spider:external:…`, all 67 from Blue Recruitment Personnel) instead carry their markup entity-escaped inside a `<p>`, which is unescaped once; their identifier is not the page id, so the id comes from the URL.
- **A hidden salary is the placeholder 1-1000.** Checked against the page state on 61 postings: every `baseSalary` of exactly `minValue: 1, maxValue: 1000` belonged to a compensation with `visible: false` and different real figures; every other range equalled the visible one. `maxValue: 0` means no upper bound.
- **Places.** `TELECOMMUTE` is remote and its places are the countries it hires from (up to 27). A remote posting with no place is the site's "Remote - Anywhere", whose `applicantLocationRequirements` is a fixed 49-country filler and is not read. An on-site place's `streetAddress` is sometimes the city ("Butte") and sometimes a street ("Cra. 14 # 97-63"), so it is used only when it holds no digit. One posting whose body says "Hybrid / New York" is `TELECOMMUTE`; the platform's flag is taken as stated.
- **A broad marketplace, mostly remote LatAm and US.** The title dictionary calls 276 of 2,427 technical and 133 confirmed non-technical; the latter are never stored, so their pages are re-bought every run (~133 requests). No posting page named an external apply URL (`directApply: true`), so Job.URL is the Torre page and there is no coverage gate — nor could there be, since nothing names the employer before the page is read.
- **No metering seen**: a full cold crawl (36 sitemap requests, ~2,440 pages at 8-way) took ~17 minutes with no refusal; steady state is the sitemaps plus new postings (~30 a day) and the re-bought rejects. (Re-measured 2026-10-29 from the crawl host: a page and an API request each second drew `503` on half of them, one page every two seconds none.)
- **A closed posting's page is a full HTTP 200.** What says it is closed is the page state's `<v>.status="closed"`, assigned right after `prefilledStatus`; `cmd/liveness` reads that for the postings the company-scoped sweep cannot reach (see [docs/agents/job-lifecycle.md](../../../../docs/agents/job-lifecycle.md) (2b)).
