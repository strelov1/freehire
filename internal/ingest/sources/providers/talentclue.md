**Talent Clue traps** (`talentclue`, a Spanish ATS at `<tenant>.talentclue.com`; live-verified 2026-10-27 — 160 tenant hosts in Common Crawl, 32 resolvable to a client with ~2,000 open jobs: McDonald's 828, Decathlon 389, Bravo (Dominican Republic) 245, Avanta 82, GBfoods 70, Henneo/Hiberus 54):

- **The board is the 32-hex CLIENT ID, not the tenant host.** The listing is the platform's widget API, `POST api.talentclue.com/jswidget-ajax/jswidget/jobs/<client id>/<base64 JSON filter>`, which answers the client's whole open listing in one response. No posting URL carries the id: it is printed only as `data-client-id` on the client's company page, `<tenant>/es/<company slug>` (`careers.talentclue.com/es/<slug>` redirects there), so a board is found by hand and added with `add-board`; `harvest-boards` can still probe a list of ids by running the adapter.
- **The API answers 401 without `X-Requested-With: XMLHttpRequest`**, 406 without a JSON Accept, 400 for an unknown client, and `{"jobs":[]}` — an ARRAY, where a populated answer is an object keyed by node id — for a client with no opening.
- **The listing's `subgroup` is the employer**: Henneo's client lists Hiberus's openings, Quirónsalud's its hospitals. `parent_company_name` is the group.
- **robots.txt declares `Crawl-delay: 10` on the API host and every tenant host**, so listing calls share one 10 s limiter and each board's pages are spaced 10 s apart; bodies (`div.job-description`) are bought for new postings only, at most 150 per board per run. A posting URL may 301 to a sibling tenant host (henneo → hiberus); a withdrawn one 301s to `careers.talentclue.com` and answers 403.
