**Glints traps** (`glints`; live-verified 2026-11-17 from a residential IP, through the local Scrapling fetch service):

- **Plain Go gets 403; the Scrapling `http` fetcher (curl_cffi, Chrome TLS) is served with no proxy.** Route `{ModeHTTP, false}` in `scraplingProviders`, ~1-2 s a page. The explore page was also measured 200 from the prod crawl host with and without the proxy; the sitemaps and posting pages sit behind the same edge, and the datacenter-range behaviour of the posting pages themselves is unmeasured.
- **The GraphQL API is not a way in.** `POST /api/v2-alc/graphql` (`searchJobsV3`, header `x-glints-country-code`) answers an anonymous client the same four postings whatever the filters, `SearchTerm` or `page` (all ignored; the schema validates, so the body does arrive), while the server-rendered explore page, which calls it with an SSR token, carries 30 real results with `hasMore: true`. The site's own client only fetches more when signed in, and a request past offset ~1000 errors `request offset exceeds the maximum limit`. Introspection is off.
- **robots.txt disallows `*/opportunities/jobs/explore?*`**, so the filtered explore pages (category / location partitioned, 30 per URL, `page>=2` is client-side only) are not a crawl path either. Posting pages and the declared sitemaps are allowed.
- **The job sitemaps are the listing.** `sitemap_index.xml` (374 KB) names `sitemap_job_<cc>_<n>.xml` shards of 100 postings each (every posting twice, the `/en/` locale second): on 2026-11-17 754 for `id`, 51 `vn`, 4 `sg`, 1 `my` — 810 shards, **80,757 postings**, read in ~6.8 min at two requests a second. The country comes from the shard name, so a new market arrives without a release. `sitemap_sourced_job_*` (`/opportunities/s/<slug>/<id>`, ~44k for `id`) are copies of JobStreet postings (`externalApplyURL` is a jobstreet.com page) and are not read. A removed posting answers 404.
- **The whole catalogue is crawled (widened 2026-11-17).** The slug is the title and the sitemap carries nothing else, so the first version scoped the crawl to `classify.IsTech(slug)`: 980 of 80,757 postings (1.2%; precision 30 of 30 against Glints' own "Computer & Software" category, title recall ~85%). The catalogue covers every profession now and the pipeline's own catalogue filter decides what is stored, so all 80,757 are listed and hydrated. A posting stays unseen only while it has not been read, so nothing the pipeline declines is bought twice. A random sample of 80 non-IT postings read 80 of 80 with no failure, and a re-listing later the same day read 805 shards and 80,186 postings (the sitemap moves), with 20 of 20 hydrated postings read (cap 20) in 7.2 min including the listing. `IsTechHint` is set only where Glints itself files the posting under "Computer & Software" (the structured statement); the rest is left to the dictionaries.
- **`fullCatalog`, so a shard that stays unreadable fails the crawl.** Each shard is asked up to three times (the tier's client does not retry). A shard listing no posting, or a listing with no posting at all, fails too.
- **A posting page has everything.** `__NEXT_DATA__` `props.pageProps.initialData.data` carries `status` (`OPEN`), `createdAt`, `expiryDate` (a bare date or midnight Z), `type` (FULL_TIME/PART_TIME/CONTRACT/PROJECT_BASED/INTERNSHIP), `workArrangementOption` (ONSITE/HYBRID/REMOTE), `minYearsOfExperience`, `salaries[]` (`salaryType` BASIC, `salaryMode` MONTH.., `CurrencyCode`, shown only when `shouldShowSalary`), the location chain (district, city, province, country) and `hierarchicalJobCategory` with its parents. The HTML body is the page's ld+json `description` (the state holds only a Draft.js document). The category id of "Computer & Software" (`9dd9bc4d-38d5-4b5e-876a-de19bc22da45`) sets `IsTechHint`.
- **The location line drops the district**: it is a neighbourhood ("Kemantren Jetis") the geography dictionary cannot place; the city, province and country are joined instead. Skills are not mapped (free-text names, not the canonical vocabulary); the dictionary reads the body.
- **The run is bounded**: 1200 new postings a run (`glintsMaxNewPerRun`; 500 of them the moving backlog window from `hydrationLanes`, which only matters for pages that failed to read and would otherwise sit at the head of the queue), two requests a second, 4 workers. Through the Scrapling tier on the crawl host a page took ~2.4 s. The first production run (2026-11-17) read 1,076 pages before its 60-minute deadline under the old 3000 budget, so 1200 is ~48 minutes with the ~7 minutes of shards. The first ~65 runs walk the 80k backlog; after that a run buys only what the sitemap added.
- **Boards**: boardless, one row for the provider (`cmd/add-board --provider=glints`); schedule with `cmd/schedule-board --manage`. A full run is ~35 minutes (7 listing, ~25 detail), so give the unit a timeout of an hour or more.
