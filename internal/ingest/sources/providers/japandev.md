**Japan Dev traps** (live-verified 2026-09-12):

- **Use the sitemap, not Algolia.** `/sitemap.xml` is a public sitemap index pointing at `/cdn/sitemaps/sitemap.xml`; the leaf carried 290 canonical `/jobs/<company>/<slug>` URLs while `/jobs` reported 294 live jobs. The sitemap is therefore the cheap discovery layer but NOT structural proof of the whole catalogue. `japandev` must never claim `fullCatalog` or `fullBoardListing` while those counts can differ.
- **Hydrate by the sitemap slug.** The final URL segment is the external id because it is known before fetching the posting page. Seen postings cost no detail request; a first bootstrap is ~290 pages and steady state is only new postings. A failed new detail is deferred rather than stored body-less, so it is retried on the next crawl.
- **The page's primary job is structured Nuxt SSR state.** `#__NUXT_DATA__` is JSON but devalue/reference-indexed: object values are indexes into the top-level table. Resolve the semantic object carrying `job`, then that job's scalar/company/skills references. Do NOT pick the first object with job-looking fields: the same page also embeds related/featured jobs.
- **Keep the employer's official apply URL when stated.** `application_url` commonly points at Lever, Workable, HRMOS, etc.; use it as Job.URL and preserve Japan Dev's attribution query parameters. Fall back to the Japan Dev detail URL when the source uses email/internal apply and states no external URL.
- **Structured source labels stay structured, not guessed.** `remote_level`, `employment_type` and `seniority_level` map only to exact freehire vocabulary counterparts. Japan Dev's Japanese/English labels, candidate-location and visa-sponsorship facts have no lossless Job fields, so retain them as a short source-fact paragraph ahead of the body instead of inventing CEFR or work-authorization semantics.
- **Do not force Japan on worldwide-remote jobs.** The board itself is Japan-focused, but `remote_level_full_worldwide` + location `Remote` does not state a workplace country. Leave Countries empty for that shape; other postings use `jp` from the source's Japan market/location scope.
- **No metering observed at `defaultDetailWorkers` concurrency.** Live-checked 2026-09-15: two bursts of detail-page fetches (8 concurrent, matching the adapter's fan-out, then 40 more at the same concurrency drawn from later in the sitemap) all answered 200, none refused or throttled — 60 requests total against a catalogue of 290. The sitemap itself still listed exactly 290 posting URLs, matching the 2026-09-12 count. This does not rule out a limit only a full ~290-page bootstrap would reach, but it rules out an immediate block on the first real crawl, so `japandev` ships without a dedicated pacer like the other unmetered `defaultDetailWorkers` adapters.
