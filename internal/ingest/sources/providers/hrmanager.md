**HR-Manager traps** (`hrmanager`; live-verified 2026-10-19 from a residential IP and the prod host):

- **A board is the customer ALIAS, not the cid every posting URL carries.** A posting is `candidate.hr-manager.net/ApplicationInit.aspx?cid=316&ProjectId=…`, but the public job-portal API is `GET api.hr-manager.net/jobportal.svc/<alias>/positionlist/json/` and answers a numeric cid with HTTP 400 `"Value cannot be null. Parameter name: connectionString"` — the same answer an unknown alias gets. The alias is case-insensitive and echoed lower-case as `CustomerAlias`. To map a cid to its alias, read `candidate.hr-manager.net/vacancies/list.aspx?cid=<cid>`: the page embeds the API's own JSON, `"CustomerAlias":"<alias>"`. Do NOT read the alias out of the page's other `customer=` links — on energinet's page one of them was `customer=kimdemo`, a template leftover. A customer with no open posting embeds no alias at all (18 of 171 cids harvested from jobnet's outbound links).
- **`atsboard` recognises only the alias-carrying URLs**: `vacancies/list.aspx?customer=<alias>`, `Agent/Subscription.aspx?customer=<alias>` and the API's `JobPortal.svc/<alias>/…` (which a customer's own careers page calls). A cid-only posting link is declined, since no network-free rule maps it.
- **`incads=1` inlines each posting's advertisement HTML**, so the listing is the whole posting and there is no detail request. Without `take` the API answers the first 25 rows; `take=2000` is honoured in one response (`skip` pages too). A board is ONE request; a customer over 2,000 fails rather than paging. The largest customer, `mercuryeng` (663 postings), is a 12 MB answer that took 5 s from the prod host and 25 s from a residential line, hence `NewLongTimeoutClient`.
- **`PositionCountSearch` can count a posting no public view serves.** `statensrekrutteringsloesning_tr` (the Danish state's shared recruitment) counted 414 and served 413 — through the JSON at any take, through the RSS variant and on the platform's own HTML listing alike; paged with `take=1`, the server answers an empty page at the hidden row's position. The other 300 customers measured served exactly their count. So the walk tolerates a shortfall of at most `hrManagerMaxHidden` (2) and fails beyond it; the rows must still be distinct and equal the response's own `PositionCountList`.
- **The list carries one `OpenApplication` row per customer that runs an unsolicited-application intake** (`ProjectType`); it is not a posting and is skipped. Every other row was `RecruitmentProject`, and every row measured carried exactly one advertisement.
- **Location is free text, the country rarely stated.** `WorkPlace` ("Fredericia / Ballerup") is the posting's own; the customer's location picklist and the department's city are the fallbacks. `Department.Country` is filled on some customers ("Danmark") and empty on most, and nothing else states a country, so none is guessed. Timestamps are .NET `/Date(<ms>+0200)/`; `Published` is the posting date.
- **A board's company is the catalogue's, and one customer is many employers.** `statensrekrutteringsloesning_tr` lists postings for 107 state agencies (Skattestyrelsen, Statens IT, Forsvarets Efterretningstjeneste…), named only in `Department.Name`; the adapter does not read that as the employer, because on other customers the department is a store ("REMA 1000 Gram") or the customer itself.
- **Not an IT platform.** Customers include retail (REMA 1000, Flying Tiger), municipalities and regions; the catalogue filter judges each title. Nothing sets `IsTechHint`.
