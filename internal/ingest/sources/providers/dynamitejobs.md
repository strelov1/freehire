**Dynamite Jobs traps** (`dynamitejobs`, dynamitejobs.com, a remote-only board across every function; live-verified 2026-11-17):

- **There is no usable listing API.** `/remote-jobs` is a client-rendered SPA (its server HTML carries no postings, only a Pinia stub), and the data API it calls lives under `/api/`, which `robots.txt` disallows. The adapter therefore reads what the site publishes for crawlers: `sitemap/index.xml` -> `jobs-of-company.xml` + `jobs-of-category.xml`, which repeat the same postings beside skill, category and company pages. 500 distinct posting URLs (`/company/<company>/remote-job/<slug>`) on 2026-11-17 (the sitemap URL set before dedup is larger).
- **Each posting page server-renders a complete JobPosting ld+json** (~160 KB page): title, HTML body, `datePosted`, `validThrough` (+30 days), `employmentType`, `hiringOrganization`, `applicantLocationRequirements`, `jobLocationType: TELECOMMUTE`. No `baseSalary` on any of 60 sampled pages (salary is prose in the body, left to the enrichment), so no structured salary is set.
- **The id is `<company>/<slug>`**: the slug is unique only within a company.
- **Every title ends `, Remote Job`**; the adapter strips it so title classification and the role fingerprint see the real title.
- **`applicantLocationRequirements` is a list of country NAMES, and the site's region presets expand to dozens**: of 60 sampled, 39 name one country, the rest 2-5 or the Europe (~50) and Latin America (~105) presets. They map to `Job.Countries` through `location.NormalizeCountry`; the location text is `Remote - <names>` for up to five and bare `Remote` beyond, so a preset does not bury the title. A posting with no list gets no countries and the dictionaries decide.
- **Not IT-only, so no `IsTechHint`** and `occupationalCategory` ("Business Development / Sales", "Marketing", "Customer Support", ...) is not mapped: the title dictionary decides `is_tech`.
- **A gone posting is a 404**, so `detailUnreadable`'s 404/410 drop is the right reading; any other failure is an `unreadableDetail` marker. A crawl that listed new postings and read none fails.
- **Paced at 1 request a second** (`dynamitejobsRequestInterval`); `robots.txt` names no Crawl-delay and no block appeared over 60 requests at 0.5s. `dynamitejobsMaxNewPerRun` is 800, above the ~500 inventory, so the first run takes ~8 minutes and later ones only the new postings (seen postings are liveness refreshes with no request).
- **The site carries a test employer** ("DJ Audit Probe", "Pentest Probe Job", an empty body, no countries); the adapter skips it (`dynamitejobsTestEmployer`).
