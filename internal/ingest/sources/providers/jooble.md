**Jooble traps** (`jooble`):

- **The description is an excerpt only.** `snippet` is "a brief description shown in search results"; no parameter returns the full posting, and no hydration queue exists for jooble (out of scope, unlike `adzunadesc`). Treat `jobs.description` as a teaser. The snippet can carry HTML entities (`&nbsp;`) and `<b>` tags.
- **The key is a URL PATH segment** (`POST https://jooble.org/api/{key}`), so it is in every request URL, and the shared HTTP client prints the URL in every error it returns. Never log a request URL; the adapter masks the key in the errors it returns (`redactKey`) and the tests hold it. Do not add a log line or error that formats the URL or the raw client error.
- **The apply link is `link`**, a jooble.org tracking URL (`https://<cc>.jooble.org/jdp/<id>` or `/desc/<id>`), because Jooble pays publishers per click on it. It is the only URL the API gives, so a posting's liveness cannot be probed at its employer; `cmd/liveness` closes by age only (`expireDespiteRegisteredPrefixes`) and the unseen sweep waits 14 days (`joobleSweepGrace`).
- **Country = the key, not a request field.** Docs (help.jooble.org, "Important Regional Restrictions"): each Jooble domain needs its own key; a jooble.org key sees US listings only; other countries need a key issued on `uk.jooble.org/api/about`, `de.jooble.org/api/about`, and so on. The request has no country field, only the free-text `location`. The adapter therefore posts to `https://jooble.org/api/{key}` and takes `CompanyEntry.Region` as that `location` string (and `CompanyEntry.Board` as the `keywords`). **Not confirmed:** whether a regional key is posted to `https://<cc>.jooble.org/api/{key}` or to `jooble.org`. Settle it when the first non-US key arrives; today there is one key (`JOOBLE_API_KEY`) and one host.
- **Free plan: 100 requests/day per key, reset at midnight UTC** (429 beyond it, 403 for a missing or invalid key). `joobleMaxPages` x boards x runs/day is held under that by `TestJooblePageBudgetStaysWithinTheDailyCeiling`; a higher limit is a request to Jooble.
- **Not in the public docs:** the `ResultOnPage` ceiling (the adapter asks for 50 and stops on `totalCount` or an empty page whatever the server returns), the `datecreatedfrom` field and any sort order (the adapter sends the date and reads the order it is given, so an ignored field means a relevance-ordered, non-incremental crawl). Check both against the first real response.
- **`id` is documented as an integer**; the adapter also takes a string (`looseID`). `updated` is zoneless ("2023-09-15T12:55:35.3870000"), read as UTC.
- **`salary` is free text** ("17,600 UAH", "{min} - {max} {currency}") and no helper in `kit` parses that, so salary stays empty. `type` and `source` are free text too and are left to the dictionaries.
