**WORK180 traps** (`work180`; live-verified 2026-10-18 from the crawl host):

- **Reachable only from our hosts.** From a residential IP every path on `work180.com` — `robots.txt` and static assets included — answers 403 `cf-mitigated: challenge`, and neither `fingerprintHTTP` (every tls-client profile) nor a headless Chrome clears it; archive.org has been refused (429) since 2026-09-15. From the crawl host and from fsn, plain HTTP with our own User-Agent answers 200. Validate from the crawl host. `api.work180.com/graphql` is not behind Cloudflare but answers `401 You are not authorized` to every operation, `{ __typename }` included; the site calls it server-side.
- **A board is a regional site** — `au` (`en-au`, which also lists New Zealand), `uk` (`en-gb`), `us` (`en-us`), the API's own `Region` enum. Three distinct board names with an empty region, so the board-scoped close's region-ambiguity refusal never applies. A board's postings are not confined to its country (the au site lists Hatch roles in Montréal), so geography comes from each posting, never the board.
- **The listing is `/<locale>/jobs-sitemap.xml`, not the search.** The search page answers `jobCount: 100, totalPages: 10` whatever the catalogue holds, and a page past 10 repeats page 10. The sitemaps named 5,168 (au), 1,729 (uk) and 1,699 (us) posting URLs; the remaining entries are search category pages. Posting ids are unique across the three, and the URL carries the employer's WORK180 slug but not its name.
- **The posting page has two structured sources.** The schema.org JobPosting carries title, body, `datePosted`, employer, places (`address.name` is the display string; no `addressCountry`), `jobLocationType: TELECOMMUTE` and `employmentType`. The React Server Components payload (`self.__next_f.push` chunks) carries the posting's own record — `expired`, `applicationType`, and `applicationLink`, the employer's own ATS posting (Workday, SuccessFactors, PageUp, Ashby, contactrh, …). An `EMAIL` application's link is a mail relay, so the WORK180 page stays the URL.
- **It is an aggregator of first-party ATS postings, hence `CoverageGated`.** The probe is asked about the employer's WORK180 slug — the only employer identity the sitemap states — and a covered posting is yielded body-less under that same slug. A slug that spells the employer differently from freehire's company key only reads as uncovered (a page bought and then discarded by the pipeline's gate); an alias in `company_slug_aliases` fixes such a pair.
- **`robots.txt` declares `Crawl-delay: 5`, and the adapter honours it**: one posting page every 5 s across all three boards, at most 120 new pages per board per run (30 minutes), newest first. The ~8.6k first backfill therefore accretes over a couple of dozen runs; a deferred posting is never stored body-less. robots.txt disallows nothing the adapter reads.
