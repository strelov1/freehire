**HCS Hiring traps** (`hcshiring`; symplr, formerly HealthcareSource; live-verified 2026-10-20 from a residential IP and the prod crawl host):

- **The board is the tenant subdomain of `<tenant>.hcshiring.com`.** The career center is an Ember app over a keyless REST API on the same host: `GET /api/jobs?page=N` (1-based) answers `{"jobs":[...],"meta":{"totalJobs","totalPages"}}` and `GET /api/jobDescriptions?id=<id>` carries the HTML body. The app calls both under a `/<build-hash>/api` prefix taken from the page; the bare `/api` answers identically and does not move with a release. Ember pluralises and camelises the model name, so the detail path is `jobDescriptions`, not `job-descriptions` (that one 404s).
- **Ten rows a page, fixed.** No parameter (`perPage`, `per_page`, `limit`, `pageSize`) widens it, so a 259-posting tenant is 26 listing requests. The listing carries everything but the body, which is why the adapter hydrates (`HydratingSource`) — the body is fetched only for a posting the catalogue does not hold. A failed body read ingests the posting list-only (the listing is authoritative for its existence); a 404 drops it. 8 concurrent body requests drew no throttling.
- **`fullBoardListing`**: the walk reads to `totalPages` and fails unless the distinct ids equal `totalJobs`; any page failing fails the crawl. The order was stable across two full walks of the largest tenant measured.
- **An unknown tenant answers 404** with an HTML "The account does not exist." page. The shared client does not hand the body back, so it is reported as a plain listing failure rather than `ErrBoardGone`.
- **US only.** The app's own JobPosting markup states `addressCountry: "US"` and `currency: "USD"` for every posting, so `Countries` is `us` and a salary is USD. The location is built as `City, ST ZIP`: without the ZIP the location dictionary reads `Hershey, PA` as Panama.
- **The structured compensation and `googleEmploymentType` fields are declared but empty** — null on all 845 postings across 31 tenants. What tenants fill in are `publicFieldValues`, named by each tenant. Two are read: the field mapped to the platform's standard `Status` slot (only a lone "Full-Time"/"Part-Time"; "PRN", "Per Diem" and combined values are left to the parser), and a field named `Salary`, whose value the platform renders as `38.50 - 55.71 Hourly` / `110000.00 Annually` (195 of 845; "Weekly" has no `salary_period` and is dropped).
- **The vendor's other hosts are other products**: `<tenant>.hctsportals.com` (behind a captcha) and `pm.healthcaresource.com/CS/<tenant>` (the older Position Manager) share no API with this one and are not recognised by `atsboard`.
