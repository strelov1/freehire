**Catho traps** (`catho`; live-verified 2026-10-23 from the fsn host):

- **Only the posting pages refuse the project's bare User-Agent.** `freehire/0.1 (+https://freehire.me)` reads `robots.txt` and the sitemaps but gets HTTP 403 on every `/vagas/<slug>/<id>/` page, while `compatibleUserAgent` is served (so is a browser string, not needed). curl's default UA is refused even on `robots.txt`. `robots.txt` disallows `/buscar/vagas/` (the search) and allows the posting pages.
- **The sitemaps are the listing.** `sitemap-index.xml` names five `sitemap2/sitemap_vagas_<n>.xml` files (50,000 URLs each, the fifth 13,535): 213,535 distinct postings, ~6.3 MB per file, ~1.3 s each. Every `lastmod` is the regeneration day (the files are rebuilt daily, ~05:00 UTC), so it says nothing about a posting. Any file failing fails the crawl. The rest of the index lists search and profession pages.
- **The sitemap is NOT the whole catalogue, so no `fullCatalog`.** The home page claims "mais de 400 mil vagas" against 213,535 sitemap URLs, and nothing states a count the walk could be checked against; closes go through the ordinary company-scoped sweep.
- **The id is the identity; the slug is cosmetic.** `/vagas/x/38959057/` serves the same posting. A closed (or never-public) id answers **301 to the slug's search page** `/vagas/<slug>/`, never 404, so a page whose final URL lost the id is gone. The daily sitemap lags: 2 of 40 postings sampled from that morning's files had already closed by the evening.
- **Posting pages carry a schema.org JobPosting**, but two of its fields lie. `jobLocation.address.addressLocality` is the STATE's name ("Rio Grande do Sul"), so the city is read from the page header ("1 vaga - Eldorado do Sul", with a "+ N cidades" note cut); `addressRegion` is the UF. `baseSalary` is a coarse band that contradicts the figure the page shows (header "A partir de R$ 2.000,00" vs ld+json 2001-3000; "R$ 1.947" vs 2000-2000), so the salary is parsed from the header instead, monthly BRL. `datePosted` names a day as its last second (`T23:59:59Z`); the day is kept at its start. The ld+json `description` keeps the employer's line breaks, so it is the body's text, followed by the page's contract/hours facts and benefit list.
- **UF codes are ISO country codes.** "Porto Alegre, RS" parses as Serbia, "Serra, ES" as Spain, "Salvador, BA" as Bosnia, so the location is written "City, UF, Brasil" and the structured `addressCountry` ("Brasil") sets `Countries`, which overrides the parse; `FallbackCountries` `br` only when it is missing.
- **A hidden employer is dropped, after the page is bought.** "Empresa Confidencial" on 8 of 50 sampled postings and a name masked as asterisks ("****") on 2 more — ~20%. Neither is a company, and filing them would build one bogus employer holding tens of thousands of postings (the SEEK "Private Advertiser" rule). The sitemap names no employer, so this is only known after the detail request, and a dropped posting is never stored, so it stays unseen and is re-read on later runs; hydrating newest-id first keeps that re-reading behind every fresh posting rather than in front of it. The cost is real: once the backlog is stored, each run spends whatever budget the fresh postings leave on re-reading those pages. A persistent record of declined ids would remove it; nothing in the pipeline keeps one today.
- **The run is bounded.** A posting page is ~170 KB and took ~0.75 s from the crawl host; 52 probe pages at ~1/s drew no refusal. One limiter paces every request at 2/s (`cathoRequestInterval`, courtesy, not a measured limit) with three workers, and a run hydrates at most `cathoMaxNewPerRun` (3000, ~25 minutes) — the first ~70 runs work through the backlog. A live run of 15 hydrations took 11 s including the sitemaps. ~26k new ids reached the sitemap in the week to 2026-10-23.
- **`employmentType` is the Brazilian contract regime.** "Estágio" maps to internship; "Prestador de serviços (PJ)", "Temporário" and "Autônomo" to contract; "CLT (Efetivo)" (a permanent hire, hours unstated) and a two-regime value map to nothing.
- **Not an IT board.** Retail, logistics, sales and cleaning dominate; nothing sets `IsTechHint` and the catalogue filter judges each title.
