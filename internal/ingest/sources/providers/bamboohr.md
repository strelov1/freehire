**BambooHR traps** (`bamboohr`):

- **A gone board REDIRECTS; it is not a body at all.** The careers-list request 302s, the client follows it, and the JSON decode fails on the landing page's HTML — `invalid character '<' looking for beginning of value`, which read as an adapter bug. It reached 135 boards. The adapter therefore takes `JSONResolvedGetter` (`GetJSONResolved`, the JSON counterpart of the existing `GetHTMLResolved`) and reads the FINAL url: **leaving `<board>.bamboohr.com/careers` is the verdict, not any particular destination.** That is deliberate — the destination encodes WHY (`www.bamboohr.com` no tenant, `/login.php` public board switched off, `/settings/account/expired.php` lapsed, `/settings/account/temporarily_suspended`), and those reasons keep their own vocabulary, so a rule naming them would miss the next one. The destination rides in the error message instead, because they do not mean the same thing to whoever decides on retirement — `temporarily_suspended` is a board to leave alone — and learning that distinction the first time cost 138 hand-run probes. An empty final url is never a verdict: a request that got no response at all must keep reading as a transport failure.
- **Empty board** (`emptyBoardListing`): `{"meta":{"totalCount":0},"result":[]}`; an unknown board redirects to HTML.
