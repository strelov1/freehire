**VietnamWorks traps** (`vietnamworks`; live-verified 2026-11-22 from the prod crawl host, plain curl):

- **Plain HTTP is served, no proxy and no Scrapling tier.** The search API and the posting pages both answered 200 to a plain client; 30 posting pages in a row (~1.4 s each, 62-109 KB) drew no refusal.
- **robots.txt**: `https://www.vietnamworks.com/robots.txt` answers 404 (an HTML not-found page), so there are no stated restrictions; the bare host 301s to www. The search API lives on a separate host, `ms.vietnamworks.com`, which has no robots.txt of its own to consult.
- **The listing is the frontend's own search API**: `POST https://ms.vietnamworks.com/job-search/v1.0/search` with `{"userId":0,"query":"","filter":[],"ranges":[],"order":[],"hitsPerPage":100,"page":N,"retrieveFields":[...]}`. An empty query returns the whole open catalogue (8,936 postings, 90 pages, every profession). `hitsPerPage` is silently cut to 100. `page` is 0-based and ran to page 89 with no depth limit.
- **`retrieveFields` is load-bearing**: every field not named comes back as an empty value (`""`, `0`, `null`), so a missing name reads as a missing fact rather than an error. The adapter asks for exactly the fields it maps.
- **The search truncates the body** (`jobDescription` ~370-680 characters ending in `...`), so the full body comes from the posting page. There is no JSON detail endpoint (the guessed `/job-detail/...` routes 403/404).
- **`order` is ignored and the ranking shuffles between requests.** Over 5 pages (500 rows) 484-487 ids were unique (sorting by `approvedDate` or `jobId` changed nothing), so a page can repeat a posting another page gave and a posting is occasionally missed for one run. The adapter dedupes by id; the unseen sweep's 48 h grace absorbs a miss. For that reason it is NOT `fullCatalog`. `ranges` is ignored too; `filter` works for some fields (`workingLocations.cityId`, `jobLevelId`, `typeWorkingId`) and could slice the catalogue if the shuffling ever matters.
- **A posting page has the whole body in the Next.js RSC flight** (`self.__next_f.push`), no `__NEXT_DATA__` and no ld+json. The posting's record carries `jobDescription` and `jobRequirement`, each either inline or a `$<hex>` reference to a `<hex>:T<len>,` text row (seen both ways, `$26`..`$2b`). The page holds a second, unrelated record (similar postings) with its own `jobDescription`, so the body is read from the record that follows `"jobId":<id>,`, not the first match in the stream. The two parts are joined under the site's own Vietnamese section headings.
- **Anonymous postings are dropped.** `isAnonymous` rows carry the placeholder employer `Vietnamworks' Client` (3 of 400); ingesting them would pool unrelated employers into one company. A row with an empty `jobUrl` (1 of 400, a Chinese-titled one) is dropped too, since its page cannot be read.
- **Facets mapped**: `approvedOn` → posted date; `expiredOn` → application deadline (the calendar day); working-location `cityName` + "Vietnam" → location; country `vn`; `typeWorkingId` 1 → `full_time` (383 of 400; ids 5 and 6 are unnamed by the API and left unmapped); salary only when `isSalaryVisible` and `salaryPeriodId` is 1 (monthly, the only period sampled), in the stated currency (VND or USD, ~2:1 USD in the sample). `jobLevel`, `yearsOfExperience` (0 means both "none" and "not stated") and the skills are not mapped; the dictionaries read title and body.
- **`IsTechHint`** is set only for the site's own top-level function group id 5, "Information Technology/Telecommunications" (29 of 400 sampled, ~7%). The group includes telecom field work and sales engineers, which is the site's filing, not ours.
- **Titles are mixed Vietnamese and English**: 292 of 400 sampled titles carry Vietnamese diacritics (73%), most of the rest are English. The classification dictionaries are English-first, so expect most Vietnamese-titled postings to resolve no category until a Vietnamese title table exists (a separate concern from this adapter). Measured over the same 400 titles with `classify`: a category resolves for 92 (23%) and `IsTech` for 10 (2.5%); inside the site's own IT group, 16 of 29 resolve a category and 8 of 29 pass `IsTech`, which is why `IsTechHint` matters here.
- **The run is bounded**: 3000 new postings a run (500 of them the moving backlog window from `hydrationLanes`), 2 requests a second, 4 workers; the listing is 90 requests (~1-2 minutes with the limiter). The first ~3 runs walk the ~9k backlog; afterwards a run buys only what the listing added. A full first run is ~25-30 minutes of detail fetches, so give the unit a timeout of an hour.
- **Boards**: boardless, one row for the provider (`cmd/add-board --provider=vietnamworks`); schedule with `cmd/schedule-board --manage`.
