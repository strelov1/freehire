**Kenjo traps** (`kenjo`, the recruiting module of a German HR suite at `<site>.kenjo.io`; live-verified 2026-10-25 across 74 site labels in Common Crawl — 55 with openings, 505 positions, small and mid-sized employers):

- **The career site reads one JSON API on its own host**: `/api/controller/career-site/public/<site>/positions` (the site and its open positions, unpaginated, no body) and `…/positions/<customUrl>` (one position with `jobDescription.html`, `officeAddress`, `datePosted`). The same paths on `api.kenjo.io` answer 400 "Not allowed by CORS"; the tenant host answers a plain request. A position's page is `https://<site>.kenjo.io/<customUrl>`; its id is `_id`, not the `customUrl` slug, which carries edit suffixes (`…-archived-2409180733` on a live position).
- **Every label resolves**; an unknown one is a 404 "Company career site was not found." (`ErrBoardGone`).
- **A position can be published without a body**: its detail answers with no `jobDescription` key at all (five1's three). That is stored body-less, not marked — the answer is the same every run. Only a detail that is not the position (no matching `_id`) is a marker.
- **`positionType` is localised in the listing ("Vollzeit") and canonical in the detail ("Full-time")**; measured values: Full-time, Flexible, Freelance, Apprentice, Intern, Student, none. Kenjo records no work arrangement at all, so `WorkMode` is the parser's.
- **`officeName` is free text** (a city, "Deutschlandweit", or a company name); `officeAddress.city` is preferred as the location and the office name only fills in.
