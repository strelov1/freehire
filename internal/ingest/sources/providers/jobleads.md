**jobleads traps** (verified live 2026-08-30):

- **Cloudflare-fingerprint-gated end to end**: plain Go/curl → 403 "Attention Required"; Chrome-fingerprint → 200 keyless, no cookie. The adapter rides `fingerprintHTTP` (the meta/bayt/gulftalent/uber cluster); the POST-only search is what gave `PostJSON`/`fpPostHeaders` their first consumer.
- **The search endpoint IS the API** (`POST /job-search/search`, the site's own frontend call); listing content arrives client-side in a Nuxt SPA, detail over `GET /api/v3/job/detailsForAppNew/{locale}/{jobId}` (endpoint table in the frontend's `logger.*.js` chunk).
- **`totalResultCount` is the current page's count** (`preciseResultCount` always true) — cannot paginate or detect truncation; the walk ends on an empty page or at `jobleadsMaxPages`.
- **Window deep (~20-30k), volatile, off-topic past ~p50**: full at p200 and empty at p210 on one query; on-topic density 96% (p1) → 7% (p25) → ~0% (p50) on "Frontend Developer" IT. `jobleadsMaxPages` = 50 is both the loop-safety bound (adp: a tenant that ignores $skip must not loop) and the relevance cutoff. `fullCatalog` stays unsound; the 14-day `sweepGrace` absorbs the partial walk — what a keyword's cap cuts reappears in another keyword's window.
- **The vdb ranking rotates between runs** (99/100 same ids, different order, on two identical page-1 requests) — the whole case for the 14-day `sweepGrace`: 48h would phantom-close and reopen drifted postings, writing phantom removals into `job_daily_stats`.
- **Detail paywalled for logged-out callers twice**: `description` always "" and `company` = "Solo per membri registrati". Company comes from the SEARCH feed; the body is assembled from the public jobSummary/responsibilities/qualifications/benefits in render order.
- **`jobLocationType` is an array** (in_person/hybrid/remote): first-wins, in_person → onsite (not `workplaceTypeMode`, which spells "on-site"). `contractType` is structured but unmapped (no freehire value).
- **Salary stated without a period** (minSalary/maxSalary/salaryCurrency) — per the remotedotcom rule, NO salary is mapped; enrichment decides.
- **A keyword is the board, a region scopes it**: `{"alpha2Country":"IT"}` alone filters results (geo circle optional) — a board row's `Board` field carries the keyword and `Region` the alpha-2 code, added via `cmd/add-board` (there is no board file — see the block AGENTS.md's "no `sources/` directory" note).
- **A cold run is tens of hours, not minutes.** One board's walk is up to `jobleadsMaxPages` (50) pages of 100, and a first crawl details every posting it lists: 19 onboarded keyword boards × (50-page walk + up to 5,000 new-post detail calls) ≈ 96,000 requests at the shared ~1 req/s pace ≈ 24h worst case. The 14-day `sweepGrace` means nothing is falsely closed while that first pass creeps across runs, but a `Type=oneshot` timer will cut a cold run short regardless — run the first crawl of a newly added board by hand rather than relying on the schedule to finish it.
- **The feed id is NOT the detail key**: the catalog id is a 32-hex variant-scoped handle; the slug hash is 33 hex (its canonical variant = feed id plus one leading char — one live posting carried `external-4964a963…`, variant `external-cde1148…`, slug `ecde1148…`). The detail keys on the SLUG hash only — keying it on the feed id 404s everything (hit on the first prod crawl; body-less rows re-hydrated via `HydrationRetryWindow`). The feed id stays the dedup key.
- **No origin/referer needed** — the generic `fpPostHeaders` set suffices (verified by deleting both headers).
