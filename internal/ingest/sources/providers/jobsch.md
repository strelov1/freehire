**jobs.ch traps** (`jobsch`, JobCloud's jobs.ch and jobup.ch; live-verified 2026-10-29 from a residential IP and the crawl host, over 200 randomly sampled postings):

- **Two sites, one posting pool.** jobs.ch (38,331 postings) and jobup.ch (30,804) share one UUID space: 17,311 ids are on both, 51,824 distinct. A posting only jobup carries answers **404** on jobs.ch, so each is read from the first site whose sitemap lists it — jobs.ch, then jobup. JobCloud's IT vertical ictcareer.ch reads the same pool (`jcJobId`), so it needs nothing of its own. JobScout24 shares the UUIDs too, but its 8.4k postings no other site carries were ~60% Adecco staffing and it is left out.
- **The sitemaps are the listing, and they are gzip FILES** (`application/x-gzip`, no Content-Encoding), read through `GetStream`. robots.txt disallows `/api/`, so the app's own search API is off limits; `/<lang>/.../detail/<id>/` is allowed (only deeper paths are not). Each site's index names one posting sitemap per language — the adapter reads the German one of jobs.ch and the French one of jobup, which list the same ids as their siblings. Any sitemap failing fails the crawl.
- **The search pages are the only place an employer is named before a page is bought.** `?term=&sort-by=date&page=N` server-renders 20 cards in `__INIT__` (`vacancy.results.main.results`: id, title, company, place, dates), newest publication first; `sort=date` and `sortBy=date` are silently ignored. Page 101 and beyond 302 back to page 1, so the search can never list the whole catalogue: 25 pages per site (~half a day of jobs.ch) feed the coverage gate and the fresh lane, and the walk also stops at a page naming nothing new. A card naming no employer is skipped unbought.
- **The posting is read from `__REACT_QUERY_STATE__`**, the query keyed `vacancy-detail`. Like XING's it is a JavaScript object literal with bare `undefined` values (`jsUndefinedToNull` rewrites them outside strings only). `text` is the whole body (lead plus template); the ld+json description is not read, since it PREPENDS JobCloud's own AI-written summary to the employer's text.
- **Two lanes, as for XING.** A sitemap posting names no employer before its page, so a discarded one stays unseen and is bought again every run; 1,000 search-named postings plus an 800-posting window over the rest that moves every hour (`hydrationLanes`), and a fresh lane that finds fewer hands its share to the window. ~1,200 distinct postings are first published a day; the first ~30 runs work through the backlog.
- **The salary is the employer's own `salary` {unit, currency, range}** on ~4% of postings (YEAR, MONTH, HOUR seen; the top may be null). JobCloud's salary ESTIMATE is a separate query and is never read. One apprenticeship stated YEAR 1,020-1,550 CHF — a monthly wage under the wrong unit — so a yearly figure under 10,000 is dropped.
- **IT is the site's own top category, numbered per site**: `106` on jobs.ch (1,391 of 38,330, 3.6%), `702` on jobup (737 of 30,804). It sets `IsTechHint`; a third of postings carry no category at all.
- **Remote is almost never structured.** The only signal is the `working-from-home` benefit (rare), read as hybrid; ~10% mention home office or télétravail in prose, which the pipeline reads.
- **Employment type: Festanstellung (permanent) says nothing of the hours.** `employmentTypeIds` 1 Temporär / 2 Freelance → contract, 3 Praktikum → internship, 4 Nebenerwerb → part time, 5 Festanstellung → full time only when the workload is exactly 100%, part time when it tops out below; "80-100%" is neither. 6 Lehrstelle (an apprenticeship) maps to nothing.
- **The location is the city names only.** A canton code ("BE", "AG") reads as a country to the location dictionary; `locations[].countryCode` sets `Countries` when present (missing on ~15% of places and on most jobup postings) and `FallbackCountries` is `ch`.
