**Get in IT traps** (`getinit`; live-verified 2026-11-03 from the fsn host; ~1.2k `/jobsuche/p<id>` URLs in the sitemap):

- **Boardless aggregator over the public sitemap.** `https://www.get-in-it.de/sitemap.xml` is one flat `<urlset>`; only `/jobsuche/p<id>` entries are postings (the rest are city landing pages, magazine articles and company pages). The id is the number in the URL. robots.txt disallows only the `/jobsuche/feeds/` exports, previews and `/extern/`, so neither the sitemap nor a posting page is refused. Posting pages are server-rendered and answer a plain client; a page taken down answers 404 and is simply not yielded.
- **Terms of use, § 10(3): automated queries need consent, "dies gilt nicht für allgemeine Suchmaschinen sowie für Jobsuchmaschinen".** Freehire reads it as a job search engine. The adapter keeps to that reading: one request a second, two pages in flight, a bounded number of new pages per run, nothing but the sitemap and posting pages. Revisit it if get in IT objects.
- **The posting page's JobPosting is the whole posting** (`title`, `description` as entity-escaped HTML, `datePosted` with an offset, `employmentType`, `hiringOrganization.name`). One `jobLocation` Place carries an ARRAY of `address` entries, one per city, which the generic `schemaPlaces` reads as nothing — `sitemapBoardPlaces` handles both shapes. Every address states `DE`. No salary or `validThrough` appears. Mostly entry-level (students, trainees, career starters).
- Shared body in `sitemapboard.go`, which `berlinstartupjobs` also uses. Unlike the generic `sitemapldjson` provider it has a fixed sitemap, so the source has its own key and is an aggregator, not `KindOther`. Needs a `boards` row (`cmd/add-board --provider=getinit`, no board id) to be scheduled.
