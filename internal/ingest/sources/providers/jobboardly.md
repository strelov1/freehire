**Jobboardly traps** (`jobboardly`; live-verified 2026-10-17, on hire-mamas, kubernetes-jobs, qajobsboard, pcdn-global, drone-vet-1, remotejobs):

- **A board is a NICHE JOB BOARD, not an employer, and its key is the tenant subdomain** of `<board>.jobboardly.com`. Many boards sit behind the owner's own domain (kubernetes-jobs serves `kubernetesjobs.com`, remotejobs redirects to `www.remotejobs.com`); the subdomain still answers and the client follows the redirect. Every posting names its own employer, and much of a board is backfilled from first-party ATS postings (Workday, JazzHR, Microsoft's own site), so the provider is an `aggregator` but not `boardless` — the getro shape. A board that is not one DNS label fails the crawl before any request; an unknown subdomain answers 404. Aggregators are absent from `atsboard`, so a pasted link is not recognised there.
- **`/jobs.json` is the whole catalogue in one unpaginated array, bodies inline.** `?page=2` is ignored and returns the identical array; on hire-mamas (141), kubernetes-jobs (173) and pcdn-global (1,332) the array held exactly as many postings as `sitemap.xml` lists. That is what earns `fullBoardListing`. The document is rendered on request and is large — remotejobs is 1,723 postings, 31 MB, ~28s to first byte — so the provider rides `NewLongTimeoutClient`, the HumanBit case.
- **There is no posting id field; the identity is `links.self`'s last segment**, a title slug plus an 8-hex suffix. Neither half resolves alone (`/jobs/<hex>` and `/jobs/x-<hex>` both 404), so the whole segment is the external id. `links.self` is also Job.URL, on whichever host the board publishes under.
- **`application_link` is never the URL.** It is the employer's apply target as typed: an email address on some postings, a Workday login redirect on others, and on hire-mamas' elmotalent imports two hosts glued together (`https://cea.elmotalent.com.auhttps://cea.elmotalent.com.au/...`). `application.url`/`application.email` were null on every posting measured.
- **`location` is the ARRANGEMENT** (`onsite`/`hybrid`/`remote`, a closed picklist) and sets `WorkMode`. The place is `company.location`, which the posting page renders as the job's location ("Fort Bragg, North Carolina, United States" for a Booz Allen posting), and is empty or null on a remote one. `location_limits` are the countries a remote posting hires from — alpha-2 codes (`US`, `DE`), the non-ISO `UK`, a name (`United States`) or `Worldwide` — read through `countriesFromCodes`, and stand in as the location text when there is no place. The page's ld+json expands `Worldwide` into every country in the world, so it is not read.
- **`arrangement` is a picklist** (`fulltime`, `parttime`, `contract`, `internship`, `temporary`, `volunteer`, or null); the first four map, the rest are left to the description. `salary` is `{schedule, minimum, maximum}` with bounds in CENTS and an ISO currency (USD, GBP, EUR, COP, ZAR, CAD seen); `schedule` is `yearly`/`monthly`/`daily`/`hourly`, often with both bounds null. Employer-typed values are published as stated — one qajobsboard posting says `yearly` 22-25 USD.
- **Not an IT platform.** hire-mamas is a job board for mothers (lifeguards, HR partners), pcdn-global social-impact work; kubernetes-jobs, qajobsboard and drone-vet-1 are technical niches. Nothing sets `IsTechHint`; the catalogue filter judges each title. No metering seen over ~20 requests.
