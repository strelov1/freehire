**BrassRing traps** (`brassring`; live-verified 2026-11-03, on sjobs.brassring.com ADM (52 postings) and xjobs.brassring.com Caterpillar/Progress Rail (131)):

- **A board is `<host>?partnerid=<n>&siteid=<n>`**, the host included because the pair means nothing on another region's host. `brassringBoardIdentity` folds key case, key order and host case into one board; the host must end in `.brassring.com`, since it is spliced into a URL.
- **The JSON API answers only inside the session the home page opens.** The home page's GET sets cookies and embeds two hidden inputs: `__RequestVerificationToken` (sent back as an `RFT` header, NOT the usual CSRF header name) and `CookieValue` (sent back as `encryptedSessionValue` in every body). Without them the API answers a bare 500 page. The jar is host-scoped, so the whole crawl of one host is serialized (`keyedMutex`), as taleo's is.
- **`ProcessSortAndShowMoreJobs` lists, 50 a page, and states `JobsCount`.** `PowerSearchJobs` returns page one only. The walk fails if it ends short of the stated total, so a truncated board never passes for a small one.
- **The listing's `jobdescription` is only a summary on some tenants** (150-400 characters on Caterpillar), so the body comes from `JobDetails` per posting the catalogue lacks. A listed posting whose detail request fails is `Unreadable` (never dropped), except on 404/410.
- **Field numbers mean different things per tenant** (`formtext8` is a city on ADM and a free-text title on Caterpillar), so none is read by number. The body is every `textarea` field in display order under its label (a label wrapped in `<!-- -->` is the tenant's admin note, unwrapped); the location is the fields LABELLED city, state/province and country, else the first labelled "...location". **ADM labels none of its location fields, so its postings carry no location** (the title ends "- Chicago, IL"): reading an unnamed field as a place would be a guess.
- **No posting date.** The listing's `lastupdated` moves with every employer edit, so it is not used as `PostedAt`.
- No request limit is documented and none was seen: ADM's 52 postings took 8s and Caterpillar's 131 took 12s at 4-way detail fan-out. No `atsboard` row: a board here needs the host plus two query numbers, which no existing recognizer mode (`querypair` drops the host) carries.
