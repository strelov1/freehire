**d.vinci traps** (`dvinci`, a German ATS; live-verified 2026-10-25 across the 102 tenant hosts Common Crawl names — 93 live, 5,336 publications, ~7% with a technical-looking title, ~90% in Germany):

- **The board is the careers HOST, and the whole board is one keyless JSON document**, `https://<host>/jobPublication/list.json`, with every live publication's body sections, places (with ISO country), working times, salary and employer — no detail request. `<tenant>.dvinci-hr.com` (the full product), `<tenant>.dvinci-easy.com` (the small-business one) and `<tenant>.dvinci.de` serve the same document, and so does an employer's own domain on the platform (`dertouristik.dvinci-hr.com` 301s to `career.dertour-jobs.com`) — which is why the board is the host and not a slug. A host-keyed board cannot be folded by URL, so the same tenant under a vendor host and its own domain would be two catalogue rows; the harvest seed should name the host the vendor host redirects TO.
- **One opening, several publications.** An opening (`jobOpening.id`) is published once per language (weig: `Ausbildung zum Papiertechnologen` beside `Training as a paper technologist`) AND sometimes several times in one language under different titles (cadenas: `(Senior) IT Administrator` and `DevOps Engineer` on one opening). Only the first kind is one job: the adapter keeps the lowest publication id of an opening whose publications are all in different languages, and keeps every publication of an opening that repeats a language. Measured: 19 translation groups, 44 same-language ones.
- **The body is `renderedContent` when it has text**, in page order (`introduction`, `tasks`, `profile`, `weOffer`, `additionalInformation`, with their headlines); `position` is the page header and `contact` names a recruiter with a phone number, so neither is body. A tenant on the plain template has no `renderedContent` and only the raw `introduction`/`tasks`/`profile`/`weOffer`/`closingText` fields. ~2% of publications have no body at all.
- **There is no work-mode field.** "Mobiles Arbeiten"/"Homeoffice" appear mostly in `weOffer` as a perk (364 of 4,535 bodies mention one), so nothing is set structurally and the description parser decides. `workingTimes` is a tenant-extensible picklist (`TEILZEIT_5075`, `VOLL_ODER_TEILZEIT_NACH_VEREINBARUNG`); only a single `FULL_TIME`/`PART_TIME` (or `VOLLZEIT`/`TEILZEIT`) is mapped. `contractPeriod` is free-form too and is not read.
- **Posted date is the publication's `startDate`** (`2018-09-10T22:00Z`, no seconds) and falls back to the opening's `createdDate`.
- **A tenant with the document switched off answers HTTP 422** `{"errorMsg":"An error has occurred"}` (doppelmayr, landgard, soprema). It stays an ordinary failure, not `ErrBoardGone` — the same body could be a transient server error.
- **The document can be large** (toom-baumarkt: 910 publications, 22 MB), so it is read through `GetJSON`, never `GetText`.
