**Careerjet traps** (`careerjet`):

- **Keyed, and the key is not enough.** API v4 (`search.api.careerjet.net/v4/query`) takes the key as HTTP Basic username, empty password (no key: 401). It also REQUIRES `user_ip` and `user_agent` on every request (missing: 403). The adapter registers only with both `CAREERJET_API_KEY` and `CAREERJET_USER_IP` set (the server's public egress IP); the user agent is the fixed `freehire-ingest/1.0 (+https://freehire.me)`. Shortcut: we crawl server-side, so Careerjet may not pay for these clicks; upgrade to a live user-triggered search if they flag it.
- **A board is a keyword search; the region is the locale.** `board` = keywords, `region` = `locale_code` (`en_GB`, `en_US`; an unsupported one is 400). The location is left empty (country-wide). `sort=date`, so a bounded crawl reads the newest postings.
- **`type: LOCATIONS` means no search ran.** The API answers 200 with `{"type":"LOCATIONS","locations":[...]}` when it reads the query as a place name. The adapter treats any answer that is not `type: JOBS` as a board config error, never an empty feed.
- **The description is an excerpt** (`fragment_size`, default 120 characters). There is no full-text endpoint and no hydration queue (out of scope).
- **Depth is capped at 10 pages x 100** (`page` 1..10, `page_size` 1..100), so a board never reads past 1000 hits however many `hits` reports. `careerjetMaxPages` is that cap.
- **No job id in the payload.** The external id is a hash of title+company+locations+excerpt (the excerpt separates two vacancies of one employer with the same title and place; an edited posting reads as a new one and the old one is swept). The tracking `url` (`jobviewtrack.com/v2/...`) is a per-click link and its stability across requests is UNVERIFIED (written before we had a key), so it is the job's `url` but not its key. Check two live requests for the same hit; if the path is stable, key on it and drop the hash.
- **Liveness cannot be probed**: every url is a tracking link, so the sweep grace is 14 days and `cmd/liveness` age-expires the source (`expireDespiteRegisteredPrefixes`). It is in `optionalExpirePrefixes`: a liveness host without the credential still runs and still age-expires it, because the fallback reads the taxonomy registry.
- **Salary** `salary_type` is Y/M/W/D/H. Weekly has no freehire period, so a weekly range is dropped whole.
