**CryptoJobsList traps** (`cryptojobslist`; live-verified 2026-11-17 from a residential IP, NOT from the crawl host):

- **Cloudflare refuses a plain client for the posting pages and the API** (`cryptojobslist.com/jobs/<slug>` and `api.cryptojobslist.com`: 403). The Scrapling tier's `http` fetcher with no proxy was served 48 of 50 sampled pages; the other two were the site's own 404s. `browser` was never needed. The sitemap and the RSS answered 200 to a plain curl from the residential IP, but they sit on the same protected host and the datacenter IP is unmeasured, so the one sitemap request rides the tier as well (`scraplingProviders` row: `http`, no proxy). **If the crawl host draws challenges, add the proxy first, then the browser.**
- **The listing is `/sitemap-jobs.xml`**: 652 postings, flat, with a `lastmod`; the index at `/sitemap.xml` also lists company, talent and blog sitemaps that are not read. `https://api.cryptojobslist.com/jobs.rss` carries only the newest 100, with a full body but no location, date or salary, so it is not used. The posting's identity is its **slug** (`/jobs/<title>-<place>-at-<company>`, with a `-1` suffix on a clash); there is no numeric id in the URL.
- **The page's `__NEXT_DATA__` (`props.pageProps.job`) is the posting**: `jobTitle`, `jobDescription` (HTML), `jobLocation` (free text: `Remote`, `Canada`, `New York, NY / London, GB - Remote (within locations)`), `companyName`, `remote`, `employmentType` (`FULL_TIME`, `INTERN`, `CONTRACTOR`), `salary` (`minValue`/`maxValue`/`currency`/`unitText`, 21 of 48 sampled), `createdAt`, `publishedAt`, `applicationLink`, and the `published`/`isActive`/`filled`/`removed` flags. The page also carries a JobPosting JSON-LD, but the state is the richer of the two. A page is ~135 KB.
- **`publishedAt` is NOT the posting date**: the site moves it forward (39 of 48 sampled differed from `createdAt`, many by months; a January posting read as published today), so `PostedAt` is `createdAt`.
- **~4% of sitemap entries answer 404** (2 of 50), a posting taken down but not yet dropped from the sitemap; that is the site saying it is gone, so it is dropped. A 200 without the state (a challenge page) is no answer, and a run that asked for pages and got none fails.
- **~77% are reposts of an ATS board we crawl**: of the 48 sampled `applicationLink`s, 12 Ashby, 10 Lever and 9 Greenhouse (65%), 4 Workday and one each Breezy and Gem (77% with those); the rest are employers' own sites (Coinbase 4, eToro, Microsoft), LinkedIn or none. So the provider is an `aggregator` and the aggregator-suppression pass is what keeps the copies out of search; the employer is only known after the page is bought, so no coverage gate can skip the request and a discarded posting stays unseen. The run therefore takes the newest 300 unseen postings plus a moving backlog window of 150 (`hydrationLanes`), one request a second, stopping 5 minutes before the deadline.
- **Not every posting is technical** (`category` is empty on 47 of 48, `tags` mixes `non-tech` with stacks), so `IsTechHint` is not set and the pipeline's own filter decides. Not `fullCatalog`: nothing states how many postings the sitemap should hold.
