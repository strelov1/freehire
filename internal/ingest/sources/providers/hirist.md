**Hirist / iimjobs traps** (`hirist`, `iimjobs`; live-verified 2026-10-25 from a residential IP and the crawl host):

- **Two sites, one backend, two providers.** hirist.tech (IT) and iimjobs.com (management, finance, IT) run the same Next.js app over the same API, each on its own host (`gladiator.hirist.tech`, `gladiator.iimjobs.com`) with its OWN posting database — a hirist id answers 404 on iimjobs. One adapter, parameterised by `hiristSite`. Plain HTTP passes from the crawl host under our own User-Agent; no proxy, no Scrapling. Both `robots.txt` ask for `Crawl-delay: 10` on the web host and the API host publishes none; every request of a run is paced to one a second (`hiristRequestInterval`).
- **A board is a CATEGORY id**, the `categoryId` of `GET /job/category/?categoryId=N&page=P&size=100` (header `version: 2`, as the web app sends). hirist's live categories are 1–17 (~29.6k postings on 2026-10-25, matching its 29,853-URL job sitemap); iimjobs' are 13 Banking & Finance, 14 Sales & Marketing, 15 IT & Systems, 16 Consulting, 17 HR, 19 SCM & Operations, 21 Legal, 22 BPO and 25 GenAI (~25.5k, matching its 25,654-URL sitemap). An unknown id answers 0 rows. Categories do not overlap (0 shared ids between 1 and 6 on page 0).
- **`totalPages` rounds DOWN.** Category 9 held 103 postings, answered `totalPages: 1`, and page 1 still served the last 3. The walk follows `hasMore` and an empty page instead. Page 0 is promoted postings first, not newest first, so the rows are re-sorted by `createdTimeMs` before the detail budget is spent.
- **A listing row is everything but the body.** `GET /job/detail?jobcode=<id>` carries it in `introText` (HTML, ~0.6–4.5k characters). A gone id answers `404 JOB_NOT_FOUND`; the web app also sends its reader home on `hasExpired`, `permanentlyRemoved` or `state == 2`, and so does the adapter. New postings only (`HydratingSource`), newest first, at most 1,200 detail requests a RUN and 300 a board, claimed in a sequential pass before any request goes out, so concurrency cannot spend the budget on an older posting. A cold start is ~30k (hirist) and ~25k (iimjobs) details, ~25 runs each.
- **Roughly half of hirist is copied from employers' own careers sites.** The detail's `crawled` flag was set on 23 of 40 sampled hirist postings (12 of 40 on iimjobs), and the employers are the Procores and Cargills we already crawl from their ATS. The adapter is `CoverageGated`: a posting whose employer a non-aggregator source already covers, or whose title the catalogue filter rejects, is yielded body-less with no detail request, so the pipeline counts it and the budget is not re-spent on it every run (the trap the naukri audit above describes). Native postings name agencies as often as employers (`HiringBlaze`, `HR LOBBY`); a `confidential` row hides the employer and is dropped before any request.
- **The title carries the employer.** Most titles read `PTC Software - Technical Lead - Full Stack Development` under the company `PTC`. The prefix is dropped when its first word is the company's (skipping a leading "The": `Hartford - Senior Director` under `The Hartford`), so the role matches the same posting elsewhere; a head that is not the employer (`Manager/Senior Manager - Full Stack & Generative AI`) stays.
- **Places are the site's own vocabulary.** `Gurgaon/Gurugram`, `Cochin/Kochi`, `Trivandrum/Thiruvananthapuram` and `Bangalore` already resolve through the location dictionary to their canonical cities. `Anywhere in India/Multiple Locations` would read as remote work ("anywhere") and is rewritten to `India`; `Delhi NCR` is rewritten to `Delhi`; `Others`, `Any Location`, `Metros` and `Overseas/International` are dropped. `Remote` is a place: a posting whose ONLY place is Remote is `remote`. The posting-level `workFromHome` flag is NOT mapped — it is set on postings whose only place is an office city (19 of 300 rows, Bangalore and Pune among them). `FallbackCountries` is `in`, since a few postings are in the Gulf.
- **Salary is in lakhs per annum.** `minSal: 30, maxSal: 45` is the "30-45 LPA" the site shows, so the figures are multiplied by 100,000 and published as INR a year — only when `hideSal` is 0 (9 of 300 hirist rows; 3 of 40 iimjobs details). `min`/`max` are the experience range in years; `min` above 0 becomes `ExperienceYearsMin`, and seniority is left to the title dictionary.
- **Tech hints.** hirist's categories are all IT functions except 4 (semiconductor/VLSI — hardware), 10 (product design), 12 (product management) and 13 (business analysis/project management); the rest set `IsTechHint`. On iimjobs only 15 (IT & Systems) and 25 (GenAI) do.
- **Not `fullBoardListing`.** Nothing states that the walk saw the whole category, and a later page failing ends the walk with what was read.
