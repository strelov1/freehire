**ITJobs.pt traps** (`itjobs`; live-verified 2026-10-27 from a residential IP):

- **Plain HTTP passes; `robots.txt` names no Claude agent**, asks `Crawl-delay: 1` and disallows the listing's FILTER parameters (`?location=`, `?work_model=`, `?remote=`, `?company=`, `?q=`, ...) — not `?page=`. So the walk is the plain `/emprego?page=N`; a filtered list is never requested. `sitemap.job.xml` names every live posting too, but only its URL, which spells the title and not the employer, so it cannot feed the coverage gate.
- **The listing is `/emprego?page=N`, 16 postings a page, 52 pages (825 postings) on 2026-10-27.** Past its end the site answers **200 with no card**, so the walk stops at the first card-less page. Every page repeats one or two promoted postings ("Em destaque") above and between its own list; they are the same `div.list-title` / `div.list-name` / `div.list-details` triple and are deduplicated by id.
- **The card carries everything but the body**: title, employer, places ("Aveiro, Coimbra, Porto", absent on most remote postings), the work model and, on ~3%, a salary. So the adapter is `CoverageGated` without a request. Each fact is an icon followed by its text (`fa-map-marker`, `fa-car-building`, `fa-coins`); the schedule fact is commented out in the markup.
- **The work model is a structured field on every posting** — the card's `fa-car-building` line and the posting page's "Modelo de trabalho": `Remoto` = remote, `Híbrido` = hybrid, `Presencial` = onsite. The JSON-LD says `jobLocationType: TELECOMMUTE` on remote postings only, so a hybrid posting's JSON-LD says nothing; the card is read first. Measured over the whole catalogue on 2026-10-27: 151 remote (18%), 454 hybrid (55%), 220 on-site (27%).
- **The posting page's schema.org JobPosting is the body**: `description` (HTML), `datePosted` (a bare date), `hiringOrganization.name` (+ `sameAs`, the employer's website), `jobLocation` as an ARRAY of Places with `addressCountry` "PT" — or as ONE Place carrying only the country on a remote posting — `baseSalary` in EUR a YEAR on few, and `employmentType` as one enum or a LIST (6 of 60 sampled, e.g. `["FULL_TIME", "CONTRACTOR"]` for "Contrato sem termo, Prestação de Serviços"); a list mapping to more than one value states nothing. A gone posting answers **404**; a listed posting whose page lacks its JobPosting is deferred, not read as gone.
- **Every posting is technical** — the board lists IT jobs only, so every posting carries `IsTechHint`. 129 employers on 2026-10-27, most of them IT consultancies and staffing firms (Outsoft, Dellent, Randstad Portugal, ...).
- **The run is bounded, and stops short of its deadline.** One limiter paces every request at one a second (the site's own Crawl-delay) with two workers; a run reads at most `itjobsMaxNewPerRun` (1,200 — the whole catalogue, so the first run takes all of it in ~15 minutes) unseen postings, newest id first, and stops hydrating `itjobsDeadlineMargin` (5 min) before its context deadline — a hydrating crawl writes nothing until `FetchNew` returns, so a run that hits its deadline stores nothing.
