**Cake traps** (`cake`; live-verified 2026-10-25 from a residential IP and from fsn):

- **The search reads at most 499 rows per query.** `page * per_page` must stay below 500 and `per_page` is capped at 50, so the adapter reads 45 rows over at most 11 pages. A query matching more answers `total_entries: 500, total_relation: "gte"`, so `"eq"` with a total inside the window is the only proof a slice was read whole. The whole catalogue (~16k postings, ~3.3k under the `it_` family) is read as slices split recursively over the platform's own facets — professions, then job type, seniority, experience bracket, remote mode, management span. Each is a partition: the 392 leaf professions' totals summed exactly to their 20 families', and every other facet's values summed exactly to the slice they split. Only LEAF professions (`family_leaf`) are queried; a family value overlaps its leaves. `available_facets` lists the whole catalogue's values whatever the filter, so a split also queries values the slice does not hold (an empty answer costs one request).
- **Two slices exceed the window on every facet** — a retail chain's full-time entry-level store vacancies and a process-engineering associate block, hundreds of near-identical postings each. Their first 495 rows are read and the run logs the count; postings past that depth are not seen.
- **The crawl hosts' IPs are Cloudflare-challenged** (403 `cf-mitigated: challenge` on api and www alike), and one exit is refused with 429 / `Retry-After: ~50` after ~40 requests a minute — the fixed proxy exit too. The rotating gateway was served 60 of 60 searches, so `cake` is in both `proxiedProviders` and `rotatingProxyProviders`, and a refused request (403/429) is retried through a fresh exit. The project's own User-Agent is accepted.
- **The search's description is plain text; the detail (`GET /jobs/{path}`) carries the HTML body, a separate `requirements` section, `created_at`, each location's `country_code` and the `remote` mode.** It is bought only for postings the catalogue lacks (HydratingSource), at most 2,500 a run. A gone posting answers 404 `"The job is not found"`. The detail carries no company name (`page_path` only), so the employer comes from the listing row.
- **`path` is the identity**: the detail resolves by it alone, so it is unique across employers, and the listing carries no numeric id to use instead.
- **A 0.00–0.00 salary means not stated**, and `hide_salary_completely` / `hide_salary_max` hide what the employer typed. `profession_v2` under `it_` sets `IsTechHint` — all 49 IT leaves are technical crafts — and is otherwise left to the dictionaries, as are the `associate`, `mid_senior_level` and `director` seniority levels, which each span two of ours.
