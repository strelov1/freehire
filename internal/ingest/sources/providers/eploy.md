**Eploy traps** (`eploy`; live-verified 2026-10-15, on jobs.ocs.com, careers.pei.group, <https://www.homeservejobs.co.uk>, jobs.manchester.gov.uk, jobs.le.ac.uk, careers.allpay.net):

- **A board is a careers HOST.** It can be the employer's branded domain or its `<tenant>.eploy.net` host (often `<name>web.eploy.net`); both serve the same site. Only the eploy.net form can be derived from a URL, so `atsboard` recognises that one. A branded domain is invisible to it, like every vanity host.
- **The list is `/live-jobs.xml`**: a sitemap of every live vacancy in one unpaginated document. That avoids the results pager, which is an ASP.NET Web Forms postback. A branded site's sitemap commonly names the tenant's eploy.net page (careers.pei.group lists `peigroupweb.eploy.net/vacancies/...`). That is the same vacancy, so a `<loc>` on the board host or any `*.eploy.net` host is read, and nothing else is. The external id is the number in `/vacancies/<id>/<slug>.html`.
- **The sitemap lags the site.** On OCS, 51 of 1,583 listed vacancies answered 410 Gone. On HomeServe, three redirected to `vacancies/vacancy-not-found.aspx`, which is a 200 page without a vacancy. Both cases are deferred, never stored. `fullBoardListing` rests on the sitemap being one document: a failed or undecodable one fails the crawl, and so does a sitemap INDEX.
- **Not every template renders a JobPosting.** HomeServe's customised site has no ld+json, so the title comes from the page's `h1` (id ending `h1JobTitle`) and the body from `div.vac-details__description`, which every template measured carries. ld+json, when present, adds the date, address and employment type. `employmentType` is tenant free text, and its usual value "Permanent" states tenure, not hours, so it is left unmapped. `baseSalary.value` is free text ("Grade 7 - £39,906 to £46,049 per annum") and is not read as structured pay.
- **No metering seen**: OCS's 1,583 vacancy pages at the shared 8-way fan-out took 4m51s with no 429. The sitemap is ~1 request per board.
