**MojPosao traps** (`mojposao`, Alma Career's "borg" platform; board = the market's domain, `mojposao.hr` (Croatia) and `mojposao.ba` (Bosnia and Herzegovina); live-verified 2026-10-28 from a residential IP):

- **mojposao.hr refuses the crawl hosts; mojposao.ba does not.** The Croatian site sits behind a CloudFront WAF that answers "403 Request blocked" to host2, fsn, the fixed proxy exit (`SOURCES_PROXY_URL`) and the Scrapling tier (http mode, with and without its proxy, 5 of 5), site and API alike; a residential IP is served (2026-10-29). Through the rotating gateway ~25% of fresh exits were served, but an exit PINNED by number (Webshare's `<user>-<n>` in place of `<user>-rotate`) keeps both its address and its verdict: 13 of 24 pinned exits were served, and three rounds later each answered exactly as before. So the `mojposao.hr` board goes through `mojposaoLane` (`mojposaoegress.go`, wired in `ApplyProxyEgress` when `SOURCES_ROTATING_PROXY_URL` is set): it starts at a random exit of the 250 the pool numbers, keeps it while it is served and moves to the next one on a refusal or a transport error, at most 8 exits a request; a 404/410 is returned at once; 20 refusals in a row stop the lane for the rest of the run, and a listing page no exit served fails the crawl. Each run logs the lane's requests, refusals and bytes. The first live run through it: 55 requests, 0 refused, 2.4 MB read — the 15 listing pages are ~2.3 MB, a posting ~3.5 KB — so a 3-hourly cadence is ~20 MB a day of the proxy's budget. A gateway user not ending in `-rotate` cannot be pinned, and the lane then takes a fresh rotating exit per try. The Bosnian board stays direct.
- **The API proxy picks the market by the `x-app` header, not by the host.** `www.mojposao.ba/api/proxy/jobs/search` without `x-app: mojposao.ba` answers the CROATIAN pool (1,449); with it, the Bosnian one (531, 6 pages). The header is sent on every request, and the posting URL takes the board's host. An unknown board fails before any request.
- **The two markets do not shape a posting the same way.** In Croatia the employer is on each posting; in Bosnia it is only on the employer GROUP the search nests postings in (the posting has no `organization` key), so a card without one takes its group's. Bosnian postings carry empty `description`/`requirements`/`benefits` and the whole body in the designed `html` ad, which is read when the three sections are empty; their structured addresses are null and `rootPosition` is unset, so `FallbackCountries` (`ba` per board) carries the country. Many Bosnian postings are German-language call-centre roles located in Sarajevo.
- **The catalogue is the web app's own search API, and it is small.** `GET /api/proxy/jobs/search?page=N` (pages from 1, 100 postings a page grouped by employer) held 1,449 open postings in 15 pages on 2026-10-28, ~130 new a day; the `sitemap-job-*.xml` files list ~256k URLs, every posting since 2024, so the sitemap is no listing. `robots.txt` allows everything but some `?source=` variants and asks for a one-second crawl delay, which is the adapter's pace. The walk reads exactly the pages page 1's `totalPages` names and FAILS on any page failing or carrying nothing (a partial listing would let the company-scoped sweep close what it did not read). The search orders by ad type, not date, so unseen postings are sorted by `publishedAt` before the per-run budget (1,200) cuts them. Only coverage is judged on the card: the catalogue filter is not, because the card lacks the root position that sets `IsTechHint`, and the whole catalogue fits the budget anyway.
- **An employer that hides its name is the STRING `"incognito"`, not an object** (4 of 1,449). Decoding `organization` into a struct fails the whole page on it, so `mojposaoOrg` accepts the string and decodes it to an empty name; such a posting is dropped.
- **The body is three plain-text sections**, `description`/`requirements`/`benefits`, newline-separated with `- ` bullets and the odd inline `<b>`; they are joined under the page's own headings ("Potrebno obrazovanje, znanja i vještine", "Poslodavac ti nudi"). 17 of 45 sampled postings also carry an `html` "designed" ad, which is images and inline styles around the same text, and is not read.
- **Salary is NOT stored as structured fields.** `salary` is `{from,to,currency,tax}` — currency always EUR, `tax` `gross`/`net` on most salaried postings, null on the rest — and no field states the period; the site's own line is "Plaća: Od 1080 eur do 1600 eur bruto". It is kept as that line leading the body. ~12% of postings state one.
- **Geography is structured, in English.** `location.items[].address` ("Zagreb County, Croatia", "Frankfurt am Main, Germany") closes with the country, read into `Countries`; a few postings are in Germany, Austria or Slovenia. `location.summary` is the display place. `FallbackCountries` is the board's country.
- **`rootPosition` 11 ("IT, telekomunikacije") sets `IsTechHint`** — 87 of 1,449 match `positions=11` in the search, which also matches additional positions, so only the root counts. `workTypes` (`on-site`/`hybrid`/`remote`; remote 19, hybrid 71) is the work mode, preferring the most remote one named. `employmentTypes` "Permanent"/"Temporary" are durations and are not mapped; only a lone "Part-time" or "Internship" is. `requiredWorkExperience` ("1-3", "5+", "<1", "") gives the floor. `endsAt` is the last application day's end (22:59:59Z in winter), so its UTC date is that day, and is read into `ApplicationDeadline`.
- **An inactive posting answers 200 with `isActive: false`**; it is gone, like a 404.
