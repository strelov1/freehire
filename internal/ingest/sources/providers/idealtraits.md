**IdealTraits traps** (`idealtraits`; live-verified 2026-10-20 from a residential IP):

- **The board is the employer's numeric business id, and a posting link does not carry it.** The career site is `app.idealtraits.com/<slug>/<base64 of the id>/careers` (`MTE2MjI5Mg==` is `1162292`); the slug is decoration and a wrong one 301s to the right one, an unknown id answers 403 `Access denied`. A posting link (`/career/<slug>/<posting id>CPG`) names only the slug, so `atsboard` recognises the career-site URL and declines the posting link; `boardresolve` gets from a posting to its board through the career-site link every posting page carries (39 of 40 sampled posting links resolve that way, one of them through a 301 to another posting of the same employer; the 40th is a closed posting answering 410, which `boardresolve` reads as a failed fetch).
- **The listing is the career site's own pagination XHR.** The same URL with `X-Requested-With: XMLHttpRequest` answers JSON `{"joblist": <cards' HTML>, "jobcount": <total>}` for any slug and without the redirect; past the end it answers an empty `joblist`, where the plain HTML page 404s. All 39 sampled boards (1-5 postings) fit one page, so a second page carrying cards has never been observed — the walk reads until it holds `jobcount` postings and fails the crawl otherwise, which is what earns `fullBoardListing`. The 39 boards' 77 cards matched their `jobcount` exactly.
- **An empty board states `jobcount: 0` and an empty `joblist`.** Both fields must be present and non-null, the count must be nonnegative, and zero must not carry unexplained markup. That native answer earns `emptyBoardListing`; `{}`, missing fields and page shells fail. Board `1161576` still answered this exact empty shape on 2026-11-11 while its old posting returned 410. Pagination fails on a later request error, changed total, or a count shortfall; none may qualify a partial read for closure.
- **The posting page's ld+json `hiringOrganization.name` is the slug** (`Comma-Insurance`), so the employer comes from the catalogue. Its body joins the benefits picklist with `###` (`Paid Time Off (PTO)###Health Insurance###`); the adapter turns each run into a list. The work arrangement is a page field outside the ld+json, `#remote-type`: `No` (onsite), `Hybrid Remote`, `Fully Remote` — an office address with `Fully Remote` is common and is what the employer stated.
- **One host, metered per IP, with a long penalty.** 4 req/s was served for ~120 requests and then every request got 429 with `Retry-After` ~240s; 1.5 req/s held for 200 requests with no refusal. Listing and posting requests share one 1.5 req/s limiter (`pacedIdealTraitsGetter`), and the adapter hydrates only unseen postings.
- **Not an IT platform.** The customers are almost entirely US insurance agencies (Farmers, Allstate, State Farm agents); the catalogue filter judges each title.
