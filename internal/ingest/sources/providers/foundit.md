**foundit traps** (`foundit`; live-verified 2026-11-17 from a residential IP through the Scrapling tier, and from the prod crawl host):

- **Scrapling `http` WITH the proxy.** A plain Go client is refused (403, `robots.txt` included). The impersonating fetcher is served with no proxy from a residential IP, but from the prod crawl host's datacenter IP the same mode answers 403 (388 B) without the proxy and 200 with it, so the `scraplingProviders` row is `http` + proxy. The browser mode is not needed.
- **The search and detail JSON are the web app's own endpoints** (`/middleware/jobsearch`, `/middleware/jobdetail/<id>`), found in `srp-v3.js`; the SRP HTML carries no data. **Both answer HTTP 400 `content negotiation failed` unless the request has a foundit `Referer`** (any foundit URL; `example.com` fails) — no cookie, no other header. Errors also travel inside HTTP 200: a gone or unknown posting is `jobDetailStatus: 404`, read as gone, and a search whose `jobSearchStatus` is not 200 fails the slice.
- **The catalogue is huge and general**: 209,690 postings for India on 2026-11-17 (22,432 in 7 days, 80,404 in 30), every trade. The search serves at most the newest 10,000 rows per query — `start` past 9,900 silently repeats the last page — and `limit=100` is honoured (each page also carries ~22 `adsense`/`banner` rows with no id, skipped). `sort=2` is strictly newest first by `createdAt`; the default `sort=1` is a relevance order. Page 0 of 100 rows is ~580 KB, ~0.6 s.
- **Its own categories cannot scope it**: 77% of sampled postings are filed under the industry `Other`, and the designation `Software Engineer/Programmer` (18,991) holds sales managers and bankers, so no `IsTechHint` is set and no facet is a board. A board would also duplicate: the pipeline namespaces ids by board, so overlapping slices as boards stored a posting twice. The adapter is therefore BOARDLESS and walks `founditSlices` itself — 21 keyword queries over the 30-day window (`jobFreshness=30`), each under 10,000 (2026-11-17: "sap" 4,566, "software engineer" 4,194, "java" 4,118, "developer" 2,868, "devops" 2,582; "python" 8,759, "cloud" 6,763 and "sql" 7,928 were left out as mostly non-technical full-text hits) — deduplicated by id and sorted newest first. The queries search the body too, so rows like "Associate Process Manager" come back; the catalogue keeps non-technical postings, so they are stored rather than filtered. A failed slice is logged and skipped; the crawl fails only when no slice answered.
- **A posting is ~45 days live** (a sampled row's `closedAt` was 44.7 days after `createdAt`), so the 30-day window plus `founditSweepGrace` (21 days) closes a posting only after it expired. Not `fullBoardListing`.
- **The row is everything but the body.** Title, employer (`hideCompanyName` rows are skipped), places as a comma string that cannot be split ("Bengaluru, India" is city and country, "Bengaluru, Chennai, Hyderabad" three cities), `createdAt` epoch ms, `minimumExperience.years`, structured salary (`absoluteValue` annual, shown on ~4% of rows; `hideSalary`/`jobSalaryConfidential` honoured; INR and a few AED), `jobTypes` (`Contract Job`, `Work From Home`, `Jobs for Women`) and `employmentTypes` (`Full time` 99%). The detail adds the HTML `description` (~8 KB inside an ~80 KB response, mostly similar-jobs bloat; ~0.55 s) and structured places `{city, state, country}`, which replace the row's string (a trailing country-only place beside a city one is dropped).
- **96% of rows are syndicated copies** (`jobSource: SCRAPPING`, `redirectUrl` to the employer's own careers site: NTT Data, Infosys, Capgemini, Axis Bank), so much of it overlaps what we already read from the employers' ATS (`CoverageGated` yields those body-less at no cost) and naukri/shine/hirist, which carry the same large Indian employers; the cross-source duplicate suppression handles the copies. Only `jobSource: ORGANIC` rows (~4%) are foundit-native.
- **The run is bounded.** One limiter paces every request at 2 a second (burst 2) with four detail workers; a run reads at most `founditDetailBudget` (1,500, ~12.5 minutes) unseen postings, newest first, the rest deferred. The ~30k-row listing walk is ~300 search pages. Other markets (foundit.sg/.ae/.my, the same app with other channel ids) are not crawled.
