**MokaHR traps** (`mokahr`; live-verified 2026-10-15):

- **A board is a tenant careers SITE, `<orgId>/<siteId>`** — the two path segments of `app.mokahr.com/social-recruitment/high-flyer/140576` (DeepSeek), `moonshot/148506` (Kimi), `zphz/148983` (Zhipu). Moka's international deployment is `hire-r1.mokahr.com` (region `r1`, RedotPay `redotpay/100008889`); a tenant of one host is unknown to the other. `robots.txt` disallows two tenant sites (`lingjuninvest/46355`, `shopee/74378`), which the adapter refuses.
- **`app.mokahr.com` answers the listing ENCRYPTED.** `POST /api/outer/ats-apply/website/jobs/v2` returns `{"data": <base64 AES-128-CBC>, "necromancer": <the 16-byte key, new each request>}`; the IV is the `aesIv` every tenant page publishes in its init-data, `de7c21ed8d6f50fe` on every tenant checked. A padding failure means the IV moved, and fails the board. `hire-r1` answers the same body as plain JSON. The tenant HTML sits behind an Aliyun WAF cookie challenge; the API does not, and needs no cookie or special UA.
- **`limit` is capped at 50** (51+ answers code 102) and the pagination is `limit`/`offset` — `page`/`pageSize` are ignored and repeat page 1. **There is no total**: `jobStats.total` is 0 on every tenant. The walk reads until a short page and fails on ANY failed page, which is what earns `fullBoardListing`.
- **Half the tenants list rows with NO body.** Probed 2026-10-25 over 81 tenant sites: on 45 (SHEIN, Tesla, Zhihu, Vanke, Trip.com…) a listing row carries neither `jobDescription` nor `zhineng`. `POST /api/outer/ats-apply/website/job` (`{orgId, siteId, jobId, locale}`) answers both, encrypted the same way; an unknown or closed id answers `success: false`, code `703015`. So the adapter is a `HydratingSource`: a row with a body is used as is, a body-less row the catalogue holds is a `SeenRefresh`, and only a NEW body-less row costs a detail request. A failed detail defers the posting; `703015` drops it. 1,221 detail requests at 8 in flight drew no refusal, and both fsn and host2 are served.
- **The whole tenant is read; the tech hint comes from the tenant's own job function.** `zhineng` is each tenant's vocabulary: Zhipu files 117 of 134 postings under 其它 (other), so no function filter can scope a crawl. `classify` over the mainland tenants' titles resolved a category for 0 of 37 (DeepSeek), 13 of 100 (Kimi), 11 of 134 (Zhipu) and `ConfirmedNonTech` for none. `mokahrTechFunctions` lists the function names that state technical work outright, as seen on these four tenants (DeepSeek 21 of 37 postings, Kimi 47 of 99, Zhipu 11 of 126, RedotPay 2 of 67) — **adding a tenant means reading its function names first**, or its Chinese postings stay unplaceable. The 2026-10-25 roster pass added the IT/software names of ~40 more tenants; a bare `技术类`/`研发类` stays OUT because a pharma, property or battery tenant files lab and building work under it, and the map is shared across tenants. Names are matched with whitespace removed (`SW/ 软件开发`).
- **A location is a DISTRICT** (`cityName: "海淀区"`) under a province, with a Chinese country name; Hong Kong is country 中国, province 香港. The city is read from the administrative code's first four digits (`110108` → `1101` Beijing), the country from a small name map, a SAR from its province.
- `status: "pause"` postings are listed (7 of 339) and are skipped. Dates are zone-less China time; `openedAt` is the one every row carries. The posting page is `<host>/social-recruitment/<org>/<site>#/job/<id>` — it rendered the posting in a browser on both hosts, Kimi's `/apply/` site included. Four tenants, ~10 requests, none refused.
