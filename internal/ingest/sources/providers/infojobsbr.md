**InfoJobs Brasil traps** (`infojobsbr`; live-verified 2026-10-24 from the fsn host, including one full listing pass of every board):

- **It is not `infojobs`.** That key is infojobs.net, the Spanish site — a different catalogue, stack and transport (the Scrapling browser tier). This one is <https://www.infojobs.com.br> and is keyed `infojobsbr` so the two can never be confused in the catalogue, the facet or a board row.
- **No sitemap, and every listing is capped.** robots.txt names none (`/sitemap.xml` redirects to the 404 page); the listings it allows are `/empregos-em-<state>.aspx`, 20 cards a page. Paging is the listing script's own pager, `GET /mf-publicarea/VacancyList/GetVacancyListFragment?url=<listing>?page=N` → `{eof, listFragmentHTML}`, and it answers **page 1 again to any request without the `ab_session_id` cookie** the listing page sets, hence a cookie-jar client (one session serves concurrent walks of different listings). A listing stops serving new results at ~10,000 (around page 490 it repeats one page), so a listing whose meta description states more than 9,000 is cut by its own filter options — category (a path), then level (`im`), contract (`tipocontrato`), hours (`wo`) — read from that page rather than restated. São Paulo needed category and level cuts. A slice with no result states no number in its meta description and shows recommendations; it is skipped.
- **A board is a federative unit, plus `todo-brasil`.** Every state listing serves the state's own postings FIRST (contiguous: measured on Roraima, Amapá, Tocantins and Acre), then the same ~1.9k padding — ~930 postings of other states and ~840 that name no place ("Todo Brasil"). A state board keeps only cards whose location ends in its UF and stops at the first page with none; `todo-brasil` walks Acre's listing (the shortest) to `eof` and keeps only the "Todo Brasil" cards. A full pass found 115,140 postings and no posting under two boards.
- **The run needs 4500 s.** All 28 boards, eight at a time through one limiter at 3 requests a second (~1,000 listing requests at ~3.2/s and then the whole pass drew no refusal; the origin is the same Azure stack as Pandapé, which 403s a burst at ~6-7/s), took 36.6 minutes to list — São Paulo alone 26 minutes for 60,139. That leaves no room for writes inside the default 3000 s run, so the provider is scheduled with `--timeout=4500s`, unsharded (each shard would carry its own limiter). Each board hydrates at most 80 new postings a run (`infojobsBRMaxNewPerBoard`): ≤ ~2.2k detail requests and ~5 minutes of writes at the ~7 new writes a second measured from the crawl host.
- **Pandapé duplicates are the pipeline's to drop, not the adapter's.** InfoJobs Brasil republishes its own ATS's career sites; on a 50-posting sample 27 were confirmed on a Pandapé tenant. The adapter is an `aggregator` and a `CoverageGated` source: the card names the employer, so a company the Pandapé crawl already covers is yielded body-less without its detail request and counted `ATSCovered` by the coverage gate; the rest are marked by the periodic aggregator-ATS dedup like every other aggregator's.
- **A hidden employer is dropped at the card.** "Empresa confidencial" (6 of the 50 sampled) is not a company, as on Catho and Empregos.com.br, and since the card says so the posting costs no request.
- **The posting page is the body; its JobPosting is optional.** A posting with a place carries a schema.org JobPosting (`datePosted` with no offset — Brasília time —, `hiringOrganization`, `jobLocation.address` with `addressCountry` BR); a "Todo Brasil" posting's page carries NONE, so the body is read from the page itself for every posting: the `white-space: pre-line` text, the fact paragraphs ("Tipo de contrato e Jornada", "Área Profissional") and the "Exigências"/"Valorizado"/"Habilidades" lists. Emoji arrive as `??` from the source in every rendering. UF codes are ISO country codes, so a place is written "City, UF, Brasil". A closed posting answers **200** with "Esta vaga não está mais disponível" and no header — not a 404 — so liveness cannot use the status, and closes go through the ordinary company-scoped sweep (not `fullCatalog`: nothing proves a walk complete). An UNSEEN posting whose page answers that notice (closed between listing and hydration) is not stored and counts as an answer, so a board whose new postings all closed does not fail.
- **Card facts.** Work mode is an icon-led picklist (Presencial / Híbrido / Home office). Salary is "A combinar" or "R$ 1.625,00 [a R$ 2.000,00]" with no period; the figures on 300 sampled São Paulo cards cluster at R$ 1.6k-3k, a monthly wage, so it is published as monthly BRL from R$ 1.000 up. Employment type comes from "Tipo de contrato e Jornada" ("Efetivo – CLT - Período Integral"): Estágio is an internship, PJ/Autônomo/Temporário/Cooperado a contract, CLT full or part time by its hours; Jovem Aprendiz, Trainee and Noturno map to nothing.
- **"Vagas semelhantes" groups hide postings the walk never sees.** A card may carry a collapsed group of similar postings, expanded by `POST /mf-publicarea/VacancyList/ListCollapsedVacancies`; on Acre 25 groups held 70 members and none of them appeared anywhere in the walk. Expanding every group would roughly double the run, so they are not read — a known gap.
- **A run that cannot finish all 28 boards loses only the boards it did not reach.** Each board is an independent fetch whose postings are written when it returns, and `cmd/ingest` starts the boards waited on longest first, so the next run picks up where this one stopped. The sweep stays company-scoped with the default 48 h window: a posting on a board the run never reached is not refreshed, but it is closed only if NO run reaches its board for 48 h — at a 6 h cadence that is eight consecutive runs, while rotation reaches every board within two. A company the run DID reach through another board does not change that: the close is by `last_seen_at` against the 48 h cutoff, not by this run's listing.
- **Cadence 6 h.** A run is ~37 minutes of listing plus at most ~17 of detail and writes, so four a day keep the hydration backlog moving (~2.2k new a run) without overlapping, and leave the 48 h window eight runs deep.
- **Onboarding** is 28 `cmd/add-board --provider=infojobsbr --board=<uf|todo-brasil> --company="InfoJobs Brasil" --apply` rows and `cmd/schedule-board --provider=infojobsbr --manage --heavy --timeout=4500s --cadence=6h --apply`.
