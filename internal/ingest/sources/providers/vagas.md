**vagas.com.br traps** (`vagas`; live-verified 2026-10-23):

- **The whole catalogue is the EMPTY search, `/vagas-de-?pagina=N`.** The site's search path is `/vagas-de-<query>`, so every `/vagas-de-<area>` listing is a keyword search, not a partition: `vagas-de-tecnologia` stated 453, `vagas-de-todas-as-areas` 2 431, and the empty query 3 981 — the figure the page's own facet counts (state, hierarchy) sum to. The adapter crawled three tech keywords (~800 postings) until the catalogue became general. `/sitemap.xml` is no help: its newest `lastmod` is 2023-06-08. `/vagas/pesquisas` is disallowed by robots and not used.
- **Page N is not a fixed slice — the listing reshuffles on every request.** Even sorted `mais_recentes` (which orders by day only) the same page fetched twice from one IP came back different: two full walks read 3 260 and 3 240 distinct postings, overlapping in 2 734. So the walk does NOT use `crawlPagedLinks`: stopping at a page that adds nothing new, or at the first page that fails (7 of 100 through the production fetch path), read ~100 postings a run. It reads the heading's total on page 1 and fetches every page that total implies; a later page failing costs that page alone. Page 1 failing, or stating no total, is still the board failing. One walk reads ~78% (3 093 of 3 981 through Scrapling, 4m13s) and successive walks are close to independent, which is what keeps the ordinary 48-hour sweep safe — a posting must be missed by every run in two days. Never mark it `fullCatalog` or `fullBoardListing`.
- **Hydrating and coverage-gated.** The listing card carries the title and employer (`a.link-detalhes-vaga[title]`, `span.emprVaga`), so `FetchNewGated` yields a covered or rejected posting body-less instead of buying its detail page. Without the gate those postings — never stored, so never seen — would take hydration slots on every run (a quarter of the tech listing was covered). `vagasMaxNewPerRun` is 1 000: 30 detail pages took ~30s through the one-per-second pacer.
- **Production crawls it through the Scrapling tier** (`scraplingtier.go`, impersonating fetcher over the rotating proxy exit); `proxiedProviders` is only the fallback. The prod datacenter IPs are refused outright.
