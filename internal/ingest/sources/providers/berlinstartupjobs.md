**Berlin Startup Jobs traps** (`berlinstartupjobs`; live-verified 2026-11-03 from the fsn host; 137 postings, all Berlin):

- **Boardless aggregator over `post-sitemap.xml`** (138 entries, shared body in `sitemapboard.go`). A posting is a `/<category>/<slug>/` page; the home page and one-segment pages are not. The page carries no id the sitemap shows, so the identity is the `<category>/<slug>` path — a retitled posting is a new one, and a posting moving category changes its id. Categories seen: engineering, sales, operations, internships, marketing, product-management, finance, hr-recruiting, design-ux, seeking-co-founders, other.
- **Open to crawlers.** robots.txt bans only SEO bots and sets `Crawl-delay: 10` for bingbot alone; the job-ad terms (3.13) acknowledge that crawlers and metasearch tools may download ads. The adapter still paces one request every two seconds.
- **The JobPosting is the whole posting** (`title` as "Role // Company", `description`, `datePosted` as a date, `employmentType`, `hiringOrganization.name`, `validThrough`). The page also holds an Article block in a `@graph`, which is not it. The terms allow Berlin postings only, so a posting stating no country falls back to `de`.
- **Most apply links go to join.com**, which the `join` adapter already crawls; the dedup pass folds the copies. The source's value is the startup curation, not volume. Needs a `boards` row (`cmd/add-board --provider=berlinstartupjobs`, no board id) to be scheduled.
