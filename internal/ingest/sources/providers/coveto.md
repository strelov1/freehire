**coveto traps** (`coveto`, a German ATS at `k<customer number>.coveto.de`; live-verified 2026-10-25 — a DNS sweep of `k1`…`k99999` found 1,191 hosts, of which 972 answered, 850 had open postings, 66,443 in all, ~1.5% technical by title):

- **The tenant label is the customer number, and coveto's DNS has no wildcard**, so resolving `k<n>.coveto.de` across the number range IS the tenant list — six Common Crawl snapshots named only 100 of them. That sweep is the seed `harvest-boards coveto <file>` was first run from; the prober's own `discover` reads Common Crawl and finds the long-indexed few.
- **The whole board is one RSS document**, `/public/rss/`, unpaginated: every open posting with its title, link, `pubDate` and a `job-id-<n>` guid. Measured on a 71-posting board, its ids are exactly the ones the paged `/public/jobs/` listing walks, and the feed is not capped on the largest tenants either: k61491 lists 4,375 items against 175 listing pages of 25, k43552 6,123 against 245 (`fullBoardListing`). The body is on the posting page as a schema.org JobPosting, so the adapter hydrates; the employer is the posting's `hiringOrganization`, because a tenant posts for subsidiaries (k60360 is Stadtmission Nürnberg; its postings name PROSUM GmbH and DNE Catering).
- **An open application ("Initiativbewerbung") is a feed item whose page carries no JobPosting** — 40 of 40 sampled, across the 158 tenants that list one; coveto withholds the block because it is not a posting. Only an item whose TITLE names an open application is dropped for that; any other page missing its JobPosting is still an `unreadableDetail` marker. Marking open applications would cost every such board its unseen sweep for good: a dropped item is never stored, so never `seen`, so it is re-read and re-marked every run, and a small board's marker share stays above `maxUnreadablePercent`.
- **A white-labelled tenant links its postings on its own domain** (k43552 → `jobs.rocket-match.de`): 131 of the 850, mostly recruitment agencies, holding ~21k of the postings. The link is fetched as given.
- **Two HTML notices stand where the feed was, both under HTTP 200.** "Diese Seite ist nicht mehr aktiv." is a switched-off tenant (`ErrBoardGone`, 7 seen); "Diese Funktion wurde nicht aktiviert." is a tenant that never enabled the feed (1 seen) — its postings are live and only this path is closed, so it stays an ordinary failure.
- **`jobLocationType: TELECOMMUTE` is the only work-arrangement statement, and it is a remote one**: all 17 sampled "(Remote) …" titles and the "100% Home Office" ones carry it, "Homeoffice möglich" postings and a random sample of 85 do not. Its absence never becomes `onsite`. `employmentType` is a comma-joined list when a posting offers several (`FULL_TIME,PART_TIME`); only a single value is mapped.
- **One origin serves every tenant**, so the posting pages share one in-flight cap (`covetoMaxInFlight`, the measured 8) across the whole provider — a first crawl is ~66k page requests.
