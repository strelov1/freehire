**DigitalRecruiters traps** (`digitalrecruiters`, Cegid DigitalRecruiters, a French ATS — Clariane/Korian, O2, Segula, Decathlon, Newrest, Burger King France, Compass, the CARSAT/CPAM social-security funds, Quebec's health networks; live-verified 2026-10-28: 345 public sites with open postings among 629 hosts, ~46k listed of which ~40k are a site's own):

- **The board is the careers HOST, and it is almost always the employer's own domain**, CNAMEd to `external-career.digitalrecruiters.com` (137.74.145.234). Nothing about a host is derivable from the employer and Common Crawl cannot find them; the hosts came from passive DNS on that IP (hackertarget's reverse-IP list, capped at 500; AlienVault OTX on the IP and on the CNAME target) plus employers' career links. `atsboard` recognises only the few `<tenant>-careers.digitalrecruiters.com` sites.
- **Read the API, not the site.** Every site is a Nuxt app over `api.digitalrecruiters.com`: `GET /careers/v1/careers-sites/<host>` (404 for a host the platform does not know: `ErrBoardGone`; it also states `is_online`, `is_internal` and the locale), `POST /public/v1/careers-site/job-ads?domainName=<host>&locale=<xx_XX>&limit=&page=` with body `{"filters":{}}` (`count` + items, no body), and `GET /public/v1/careers-site/job-ads/<job ad id>?domainName=&locale=&withJsonld=1` (description, profile, `additional_info` as an OBJECT `{title,text}` or null, `brand_name`, address with country, contract, working time, and a JSON-LD with `datePosted` and `baseSalary`). The API host has no robots.txt; the sites declare `Crawl-delay: 10` and are not read. Paced at one request a second for the whole run.
- **The locale must be one the site offers**, or the API answers 400 "This locale isn't supported", and the API wants `fr_FR` where the site says `fr`. The adapter uses the site app's own mapping (`drLocales`). The locale does not filter the listing. The public page is `https://<host>/<site iso code>/annonce/<slug>` (`/fr/…`, `/fr_CA/…`, `/de_CH/…`).
- **A site may AGGREGATE others' postings**: `recrute.ouicare.com` lists 3,802, of which 208 are its own and 3,098 are `emploi.o2recrute.fr`'s. Every item names its owner in `career_domain`, and only the board's own items are read, so a posting is never stored under two boards. The listing is checked against `count` exactly (`fullBoardListing`).
- **Internal-mobility sites** (`is_internal`, e.g. `colibri.clariane.com`, `mobilite.avril.ca`) are for the employer's staff: the prober declines them and the adapter fails them.
- **The listing answers slowly**: one page of 3,802 took 33 s and a page of 1,000 took 6 s, so pages are 1,000 and the adapter runs on the long-timeout client.
- **At one request a second, the run's posting reads must be budgeted across ALL boards.** The first crawl capped reads only per site (300). Eight concurrent sites spent the run's 40 minutes hydrating the first ~45 sites, and the 160 sites that remained never had their listing read. Because the limiter refuses a wait it can already see will miss the deadline, each of them was recorded as a FAILED board. The run budget is now 1,200 reads, with at most 150 per site, which leaves ~12 minutes for the ~350 sites' two listing requests each. A wait the limiter refuses now sits out the deadline instead of failing at once, so the pipeline reads the board as interrupted, not failed.
- Slugs carry any script (`…-vandœuvre-les-nancy`, `…-niepołomice`).
