**Civil Service Jobs traps** (`civilservicejobs`; live-verified 2026-10-23 from a residential IP and from the fsn host):

- **Every path answers an ALTCHA proof-of-work page first** ("Quick check needed", HTTP 200, `id="captcha-form"`). It is a computation, not a person check: `GET /csr/index.cgi?ProtectCaptcha=1` returns `{algorithm, challenge, maxnumber, salt, signature}`, the answer is the number in `[0, maxnumber]` whose `SHA-512(salt + number)` equals `challenge` (`maxnumber` 300000, a fraction of a second), and it is POSTed back as `altcha` = base64 JSON together with the page's `originalRequestToken`. The verdict is the `protectVerification` cookie — bound to the client IP, valid ~24h — so the adapter runs on a cookie-jar client and solves once per run. `robots.txt` allows everything except `JoobleBot`.
- **The pages are Windows-1252 and declare no charset.** `£` is the byte `0xA3`, quotes and dashes `0x91`-`0x97`; the shared HTML getters parse UTF-8 and turn all of them into U+FFFD. The adapter reads raw bodies (`TextGetter`, `FormTextPoster`) and transcodes before parsing.
- **The empty search is the whole catalogue, and it is complete.** The home page's quick-search form (`#ID_context_search_form`, its hidden fields read rather than restated) POSTed with empty `what`/`where` and `overseas=1` answered "1,412 Search results"; 57 pages of 25 yielded exactly 1,412 distinct postings. A posting published mid-walk shows as one extra (1,413 against a stated 1,412), so the walk fails only when it reads FEWER than the first page's total — which, with any page failing, is what earns `fullCatalog`.
- **The posting id is `jcode`, read from the title link's `aria-describedby` (`dref-<ref>-<jcode>`).** Every href on the site is a signed, session-bound `SID`; `/csr/jobs.cgi?jcode=<id>` is the stable address and is what is stored. A closed posting does not 404 there — it answers 200 with the sign-in page, which carries no `#id_common_page_title_h1`.
- **The origin is slow, so the run is bounded.** A posting page took ~4 s to answer; one limiter paces every request at 1/s (`csjRequestInterval`, unmeasured as a limit — no refusal or second challenge across the full walk) with four detail workers so latency does not set the pace. The first run faces the whole catalogue, which fits the 50-minute run timeout only while the origin stays fast, so a run hydrates at most `csjMaxNewPerRun` (600) postings and the rest wait for the next run unstored.
- **The card is the source of employer, place and pay.** Department (the employer), location and salary are read from the listing card; the posting page's location is a prose section kept in the body. A truncated card location ends with "... see the job advert for full location information", which is cut. Of 1,409 cards with a salary every bound was annual bar two (£475, £1,000), so a range is published as GBP per year only from £5,000 up.
- **"Working pattern" lists every schedule the role allows** ("Flexible working, Full-time, Job share, Part-time" on 22 of 38 sampled), so an employment type is set only when it names one. Contract type, grade and role type have no lossless vocabulary counterpart and stay in the body's fact list. Countries are a `FallbackCountries` `gb`: `overseas=1` includes embassy postings abroad.
- **Not an IT board.** 4 of 38 sampled postings were "Digital" by type of role; the catalogue is broader than IT and the filter judges each title.
