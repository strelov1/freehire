**SkipTheDrive traps** (`skipthedrive`, skipthedrive.com; live-verified 2026-11-18 from a residential IP, not yet from the crawl host):

- **No feed or API a plain client reaches.** `/feed/` answers HTML, the REST route `/wp-json/wp/v2/job` is Cloudflare-blocked (403), and there is no per-job sitemap: `/sitemap.xml` lists only the ~23 `/job-category/<slug>/` pages. The listing is those category pages, paginated `/job-category/<slug>/page/N/` (up to 33 pages of 20), read until a page adds no new link. A category's first page failing fails the crawl; a sitemap with no category fails it too.
- **~6,700 unique postings** across the categories (measured by walking all of them); a posting sits in several, so the adapter dedups by the numeric id at the end of the slug (`/job/<company>-<title>-<id>/`).
- **The listing row has title and company, no body.** The posting page has no JSON-LD: the body is `#skipthedrive_section`, the location the text beside the `fa-map-marker` icon, the date `article:published_time`, and the link out to the employer is the `<a>` in `.apply_to_position_div`, stored as `ExternalApplyURL`.
- **~2/3 of the apply links are Ashby (27%), Greenhouse (18%), Lever (13%), Workable (9%) postings, another ~10% Workday, Breezy, BambooHR, JazzHR, Recruitee;** the rest are the employer's own site (sample of 122). Employers whose board we crawl are deduplicated by the pipeline, so the source adds the long tail and the non-ATS employers.
- **Hydrating, bounded per run** (`hydrationLanes`, 300 fresh + 300 backlog, 2 workers): the first runs drain the ~6,700 backlog over several runs. A page that cannot be read keeps the posting list-only, and a run that had pages to read and read none fails.
- The mix is mostly non-IT (sales, marketing, finance, healthcare, project management), so `IsTechHint` is NOT set.
