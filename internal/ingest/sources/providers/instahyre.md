**Instahyre traps** (`instahyre`; live-verified 2026-10-25 from a residential IP and the crawl host):

- **The search is open, the pages are not.** `GET /api/v1/job_search` answers plain HTTP from the crawl host under our own User-Agent, while every page of the site — the posting pages included — answers Cloudflare's 403 "Just a moment..." to any plain client, proxied or not. Scrapling's impersonating fetcher (`http`, no proxy) is served the pages from the crawl host's own IP at ~0.4 s each, so the provider has a `scraplingProviders` row for its pages only and keeps a plain client for the search. Without `SCRAPLING_FETCH_URL` every page read fails and the board fails as "none answered", which is the honest outcome. `robots.txt` names a sitemap and disallows nothing.
- **A board is a COMPANY-SIZE bucket** (`company_size`: `1` small, `3` medium, `2` large; anything else answers 400 "Invalid company size"). The search stops at 10,000 rows (`offset + limit` past it answers 400 "Result window is too large"), and the whole catalogue held 12,724 postings on 2026-10-25, so it has to be cut. Company size is the one filter found that PARTITIONS it — 3,705 + 6,900 + 2,119 = 12,724 exactly — where the job-function filter overlaps (backend 4,360 and full-stack 3,934 together are 5,293). A bucket past the window is read to the window and logged. The page size is 35 whatever `limit` asks; a full walk is ~365 pages.
- **A search row is everything but the body.** Title, employer, places (`locations`, comma-separated) and the public URL; the body is the page's schema.org JobPosting (`description` HTML, `datePosted` as a day, `employmentType`, `jobLocation[].address`). New postings only (`HydratingSource`), at most 600 page reads a run (the ~365 search pages answer in ~3 s each, so a full walk is already ~18 minutes of the scheduler's 2,400 s crawl budget), claimed before any request goes out, all requests paced to one a second. `CoverageGated`: a covered or catalogue-rejected posting costs no read. A closed posting's page still answers 200 but drops its JobPosting; a page without one is deferred, never read as gone, since a challenge page lacks one too and a listed posting is open.
- **"Work From Home" is one of the search's places** (1,106 of 12,724 postings; 199 of 2,119 in the medium bucket). As the only place it is remote work; beside an office it is kept as "Remote" for the location parse. `FallbackCountries` is `in`.
- **Mostly technical, not only.** The largest functions are backend (4,360), full-stack (3,934), other software (1,972) and data/ML (1,875), but support and sales roles appear ("Chat Support Associate"), so no tech hint is set. `is_sourced` was false on every sampled row: postings are the employers' own.
