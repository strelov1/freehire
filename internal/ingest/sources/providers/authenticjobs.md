**Authentic Jobs traps** (`authenticjobs`, authenticjobs.com, a WordPress / WP Job Manager board for designers, creatives and developers; live-verified from host2 on 2026-11-22):

- **robots.txt bars every query string and sets `Crawl-delay: 3`.** The `User-agent: *` section disallows `/feed/`, `/wp-admin/`, `/xmlrpc.php` and `/*?`. That removes the usual WordPress routes: REST pagination (`?page=N`, `?per_page=`), the RSS feed (also `/feed/`), and `/?p=<id>`. The adapter sends no URL with a `?` (a test asserts it) and paces every request, listing and detail alike, at one per 3 s through one limiter.
- **No sitemap, no JobPosting JSON-LD.** `/sitemap.xml`, `/sitemap_index.xml`, `/wp-sitemap.xml` and the Yoast `job_listing` sub-sitemaps all answer the 404 page, and a posting page's only ld+json block is a BreadcrumbList. So the generic `wpyoast` adapter does not fit and a board on it would crawl nothing.
- **Listing: `POST /jm-ajax/get_listings/`** (the plugin's own pager, form `page=1&per_page=200`). It has no query string, answers JSON `{found_jobs, max_num_pages, html}`, and one page held all 42 open postings. The adapter reads only each card's id and link from the HTML fragment; a `max_num_pages` above 1 fails the crawl rather than truncating it. The REST list (`/wp-json/wp/v2/job-listings`) carries the full body but is only reachable page by page through the forbidden query string, so it would yield the newest 10.
- **Detail: `GET /wp-json/wp/v2/job-listings/<id>`** (query-free, full HTML body). Fields come from `meta`: `_company_name`, `_job_location`, `_remote_position` (structured remote flag, maps to `WorkMode remote`), `_filled` (a filled position is dropped). The employment type is read from the `job-type-<slug>` class in `class_list` (`full-time`, `part-time`, `freelance` -> `contract`, `internship`), not from the term id. Salary meta is free text and is not read. A non-404 failure yields an `Unreadable` marker; a crawl that listed postings and read none fails.
- **Category names come from `/wp-json/wp/v2/job-categories/<id>`**, one request per distinct id per run. The site's categories (Design, Back-end Engineering, Front-end Engineering, AI, Marketing, Product Management, Sales, ...) are not IT-only, so `IsTechHint` is set only for `Back-end Engineering`, `Front-end Engineering` and `Artificial Intelligence (AI)`.
- **Measured size:** 42 open postings (`X-WP-Total`), almost all full-time. A run is 1 listing + 42 details + up to ~10 category lookups, about 2.7 minutes at the crawl delay. The listing is public from a plain client on host2, no proxy or browser needed.
- **Expected classify gap:** English titles; the design and marketing share (about a third) will not resolve a technical category, which is correct for those postings.
