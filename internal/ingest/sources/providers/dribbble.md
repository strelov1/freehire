**Dribbble Jobs traps** (`dribbble`; live-verified 2026-11-22 from the crawl host, plain HTTP):

- **Plain HTTP passes; `robots.txt` (`User-agent: *`) allows `/jobs` and `/jobs/<id>-<slug>`.** It disallows only `/jobs/*/apply_now`, `/*/listings`, `/*/tags*`, `/talent/matches/*` and similar account paths, none of which the adapter requests. The sitemap lists landing pages (`/design-jobs-in-germany`, ...) whose few postings are all on `/jobs` already (checked: 2 of 2 are), so it adds nothing.
- **The listing is `/jobs?page=N`.** Page 1 carries 48 postings, page 2 three, page 3 onward answers 200 with no card — 51 in all, a small board. Each card has two anchors to the same posting: the overlay (`...?source=index`) and the "View job" button (no query); only the second is matched, so the id is read from a clean path. Page 200 answers 400, so the walk stops at the first card-less page (and at a 20-page ceiling).
- **A posting whose slug ends in `-CLOSED` is still listed** (its employer closed it); it is skipped and, once it has left the crawl for the sweep's grace window, closes. A posting's page also carries a `validThrough`; one in the past is skipped. The one live sample showed `validThrough` months ahead on a posting made in 2022, so an old `datePosted` (2022 on one live posting) is normal.
- **The card has no usable category, so no posting is `IsTechHint`.** Titles are design-led (graphic, product, brand, motion), with the odd "Design Engineer"; the title dictionary decides. Expect a low `is_tech` share and many postings that resolve a design category at best.
- **The posting page's schema.org JobPosting is the body**: `title`, `description` (HTML), `datePosted` (RFC 3339), `validThrough`, `employmentType` (`FULL_TIME` ...), `hiringOrganization.name` and `jobLocation` + `jobLocationType: TELECOMMUTE`. For a remote posting `addressLocality` is the placeholder `Anywhere` or `Remote` with no region and country, which is dropped from the location text; the work mode is `remote` and a bare `Remote` stands as the location. Some postings are external listings (an intervieweb careers page) and say so in the body only.
- **External id is the numeric id** at the head of the slug (`183719`), the URL is the slug path as listed. The id, not the slug, is the identity, since a slug is title text.
- **Cost: ~55 requests a run (3 listing pages + one per new posting), paced at one a second.** Cadence daily is plenty; the catalogue is 51 postings.
