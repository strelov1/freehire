**Adzuna traps** (`adzuna`):

- **The API description is a snippet, not the posting.** Adzuna's own docs say so — "we currently only provide a snippet of the job description" — confirmed live at exactly 500 characters, ellipsis-terminated, no parameter unlocks the rest. The full text lives only on Adzuna's own hosted job page (`schema.org` JobPosting ld+json, read via `sources.LDJobPosting`) — but only the `/details/...` URL shape reaches it; the `/land/ad/...` ad-network tracking-redirect shape answers Adzuna's own branded "Access Denied" page to a non-browser request, browser-shaped headers included (confirmed live 2026-08-08).
- **`internal/ingest/adzunadesc` is the after-ingest capture queue** — the same shape as apply-form (`adzunadesc.Eligible` is the gate, mirroring `NeedsRequestCapture`), except the payload overwrites `jobs.description` directly via the existing `UpdateJobDescription` query rather than living in a new table — `adzuna_description_hydrated` exists purely as the queue's "don't ask again" marker. `cmd/hydrate-adzuna-description` drains the ongoing queue; `cmd/seed-adzuna-description-queue` is the one-off pass that queued the ~21k rows already in the catalogue from before this shipped.
- **Verified live in prod (2026-08-09):** ~6.5k fetches over the first ~8h, no blocking from Adzuna at this pace — the ~40% failure rate that first run showed was NOT blocking. Two causes, both diagnosed from `last_error`: genuinely-gone content (404, or a 200 page whose ld+json carries no JobPosting block — nothing to fix) and a real bug, now fixed: **a job's stored `url` can drift between the two shapes for the SAME posting across re-crawls** (confirmed: enqueued eligible at 03:03, re-crawled to the `/land/ad/` shape by 08:25, claimed and 403-ed three times by 10:18). `Eligible` is checked once at enqueue; the runner re-checks the URL shape on the CLAIM (which reads `jobs.url` fresh) before fetching, and `Store.Discard`s a drifted claim — deleted, not dead-lettered, so a later crawl that restores the eligible shape can re-enqueue it — rather than burning retries against a page it already knows will 403.
- **A board id repeats per country** (`it-jobs` exists once per country), which is why `board_health` carries a `region` column.
