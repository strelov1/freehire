**naukrigulf traps** (`naukrigulf`; live-verified 2026-11-22 from the prod crawl host through the Scrapling tier):

- **No posting sitemap, and the pages are a shell.** `robots.txt` (`User-agent: *`) disallows only `/advertiser/`, `/preview/`, `/photo/`, `/profilePic/`, a few `/manager` and `/ni/manager` routes and spam-keyword slugs (`/buy-*`, `/call-on*`, ...); it names `sitemap_index.xml`, whose children are search landing pages (`sitemap-Srp.xml`: ~3,800 `<skill>-jobs-in-<city>` URLs per city, `sitemap-company.xml`, `sitemap-Careercafe.xml`) and carry no posting. The search page (`/it-jobs-in-dubai`) is a 44 KB client-rendered shell with no data and no JSON-LD. So the posting set comes from the JSON API the web app itself calls, which robots.txt does not disallow.
- **The API.** `GET /spapi/jobapi/search?seo=1&showBellyFilters=false&Limit=49&Offset=N` lists, `GET /spapi/jobs/<JobId>?seo=1&xz=1_0_5&source=srp` is the detail. Found by reading the web app's `searchResult` chunk (`Offset`, `Limit:30`, `pageNo`, header `version: v1`). **Without the `version: v1` request header the search ignores `Offset` and `pageNo` and answers its first page every time**. `Limit` must be under 50 and `Offset` under 45,000 (HTTP 400 otherwise; the web app 404s past it). Total on 2026-11-22: `TotalJobsCount` 41,499 (`TotalVacanciesCount` 78,914, vacancies counted per opening). Past the end the API answers an empty `Jobs` list, which is where the walk stops; a catalogue that outgrows 45,000 needs slicing (the `Location`, `Keywords` and `Experience` parameters narrow it; `Keywords=software engineer` gave 804, with `Location=Dubai` 158).
- **The API requires the public web app identifiers.** On 2026-11-23 requests carrying only `version: v1` returned HTTP 400 asking for an App ID and System ID. Including `appid: 205` and `systemid: 2323` restored two distinct listing pages and a sampled detail on the configured route.
- **Newest first.** Page 1 is 22 Nov, offset 20,000 is 6 Nov. The adapter still walks every page (~850 at 49 each, ~1 s a page, ~15 minutes) because a refresh and the unseen sweep need the whole list; it sorts by `LatestPostedDate` so the bounded detail reads take the newest.
- **The listing is the posting minus its body.** A row carries `JobId` (stable, `ddmmyy` plus a sequence), `Designation`, `Location` (`Dubai - United Arab Emirates (UAE)`, which `internal/dict/location` resolves to a country, city and the `mena` region without help), `Company.Name`, `JdURL` (the public page, kept as the posting URL), `LatestPostedDate` (unix seconds, as a string), `Experience.Min/Max` and a one-line `jobInfo`. The full body is the detail's `Description` (HTML) plus `DesiredCandidate.Profile` (the requirements, appended under a heading), bought only for a posting the catalogue lacks.
- **Anonymous postings are skipped: ~25% of the catalogue.** 15 of the first 60 sampled postings were filed under the one name `Confidential Company` (with a per-poster `Company.Id` and `Other.isConfidentialCompany: true`). It is no employer and would build one bogus company out of them, so they are dropped from the listing before any detail is bought (hirist and kariyernet do the same).
- **Facets the detail states.** `FunctionalArea` is the site's category: `IT Software` and subcategories suffixed `(IT Software)` set `IsTechHint` (the company's `industryType` says nothing about the posting, so it is not read). `locationType` (`On-site`, null on a quarter of postings) maps to `WorkMode`, `employmentType` (`Full-time`, null on a quarter) to `EmploymentType`. Salary comes from `Compensation.jobMinCurrency`/`jobMaxCurrency` (`AED 12,000` / `15,000`) and `Other.currLabel`, only when `IsCtcHidden` is not `true` (23 of 33 sampled were hidden). The API omits the period. The public posting page and the [employer posting guide](https://www.naukrigulf.com/ni/nidownload/Naukri_gulf_Communication/Recruiter_Communication/Recruiters_quick_guide_NG.pdf) both label this field Monthly Salary. `Compensation.MinCtc`/`MaxCtc` are USD buckets for the viewer's currency and are not read. `salaryTimeBrand` was null on all 33.
- **Akamai.** From the crawl host a plain client and Scrapling `http` without the proxy both die with `HTTP/2 stream 1 reset by server (INTERNAL_ERROR)` on every path, robots.txt included; `http` with the proxy served robots, both sitemaps, the SPA chunks and both APIs, and `browser` mode also passed (needless). Some proxy exits are refused with a 403, so a 403/429/5xx is asked again up to four times (1 s, doubling); a page still refused fails the crawl when it is a listing page, and defers the posting when it is a detail. The row is `http` + proxy (`scraplingtier.go`).
- **The run is bounded.** One limiter paces every request at two a second, four detail workers, and a run reads at most `naukrigulfMaxNewPerRun` (1,500) unseen postings, newest first, so the ~15 minute listing walk plus ~12 minutes of details fits the scheduler's 2,400 s budget. The site adds roughly a thousand postings a day (the freshness cluster counts 195 postings at one day old, 1,617 at three), so a run every few hours keeps up and the ~30k cold backlog (anonymous ones aside) drains in about a day of runs. Suggested cadence: every 4 hours, timeout 2,400 s. The walk races the catalogue (postings arrive at the front while pages are read by offset), so a page boundary can repeat a posting (deduplicated) or lose one for a run; `naukrigulfSweepGrace` is three days.
- **Expected IT share.** The clusters count 3,215 postings under `IT Software` and ~420 under its network/security subcategory (~9% of 41.5k), with titles in English, so `internal/dict/classify` should resolve most of them; the rest is hospitality, construction, sales, oil and gas, medical and teaching, which the catalogue filter decides.
- **Not read.** `Contact` (recruiter details), `Other.jobRedirection` / `jobSource: TAG` (a posting that sends the applicant to the employer's own site, such as Hamad International Airport's: still listed, its URL is the Naukrigulf page), the Arabic site (`arabic.naukrigulf.com`), `nationality` filters.
