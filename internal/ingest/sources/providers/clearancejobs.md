**ClearanceJobs traps** (`clearancejobs`; live-verified 2026-11-22 from host2 with a plain client; not the same site as `clearedjobs`):

- **Boardless aggregator over the `job_postings` sitemaps.** The wildcard policy disallows `/jobs?` (search queries), `/*/apply$` and `/ux-test/`. It names `/data/sitemaps/index.xml`. Posting pages `/jobs/<id>/<slug>` answer a plain client with 200 (no Scrapling tier needed; six back-to-back reads were never refused, so the run is paced at three a second as a courtesy). The search API (`/api/v1/jobs/search`) answers 405 to a GET, and robots.txt disallows the search route, so it is not used. The index also names ~17 landing-page files (company, city, category combinations) that carry no postings; only `/job_postings*` files are read.
- **The sitemaps never forget.** 80,198 entries on 2026-11-22 (45,140 + 35,058), back to 2016, no `lastmod`; a page of an expired posting still answers 200 with a `validThrough` in the past, and a removed one 404s. Ids rise with `datePosted` and `validThrough` is a fixed 60 days after it (the file boundary is not the live boundary: `job_postings.xml` still held live postings from 2026-10-05). So the adapter binary-searches the sorted ids for the first one still live (~17 page reads) and refreshes and hydrates only the IDs above it. Boundary probes skip removed URLs and require a nearby dated posting. The adapter stores validThrough for deadline-based closure. Without that, every run would re-read the expired backlog (never stored, so never "seen") and would refresh dead postings forever, so the unseen sweep could never close them.
- **`validThrough` is `2026-12-28T16:07:03+00:00Z`**, an explicit offset plus a stray Z; `clearancejobsTime` drops the Z. An unreadable value reads as live.
- **The JobPosting is the whole posting.** Title carries a " Jobs" suffix; the body is HTML with escaped text; the clearance level is the structured `securityClearanceRequirement` ("Top Secret/SCI", "Unspecified") and is rarely in the text, so a "Security Clearance:" line is appended for the clearance dictionary (the same convention as `clearedjobs`). `industry` is the site's own category (`IT - Software`, `Management`, `Construction/Facilities`, ...); only `IT - *` sets `IsTechHint`. `baseSalary` is USD, usually YEARLY. `jobLocation` is a list of places with `addressCountry: "United States"` for domestic ones.
- **Overlap with `clearedjobs`**: both are cleared-work boards and many employers post on both; the cross-source dedup pass folds the copies, the two ids are unrelated.
- **Budget**: ~55k live postings (est.). 4,000 new pages a run (~22 min at three a second); a cold start takes ~14 runs newest-first, steady state ~1.5k new a day. Suggested cadence: every 2 hours, crawl timeout 2,400 s. Needs a `boards` row (`cmd/add-board --provider=clearancejobs --company="ClearanceJobs" --apply`, no board id).
