**Paradox traps** (`paradox`; live-verified 2026-10-20 from a residential IP):

- **The pages are walled, the API is not — but only with `X-Requested-With: XMLHttpRequest`.** Every `/co/<site>/…` page answers 202 with an AWS WAF JavaScript challenge. The front end's own JSON API (`/api/job-list-site-ui/search-job`, `/api/job-posting/get_widget_extra_settings`) answers any User-Agent, ours included, with no cookie — and 404 to the same request without that header. `robots.txt` disallows nothing.
- **A board is `<host>/<site>`, lower-cased.** Sites live on one of several instances — `olivia.paradox.ai`, `olivia.eu1.paradox.ai`, per-customer hosts like `darden.paradox.ai` — and only there. Site slugs are case-insensitive. McDonald's `www.mchire.com` runs the same software under its own domain and is not recognised.
- **Not every site has a list.** 8 of 34 sites sampled from real apply links answer the listing 404 "Site X is not found" while their postings resolve one by one; an unknown company answers 404 "Company slug X is not found". Neither is crawlable.
- **The listing is slow and paged; the total is exact.** `limit`/`page` (1-based); the server spends ~50 ms per row (100 rows 4-11 s, 2,500 rows timed out server-side), hence 100-row pages on the long-timeout client. A page past the end states `total_jobs: 0`, so the total is read from page 1, and the walk fails unless the distinct ids equal it (`fullBoardListing`). InspireBrands2 walked to 2,064 distinct of 2,064 under the default sort; a total can move by one between runs, which fails that run's board rather than truncating it.
- **The listing body is a 250-character preview**, so the adapter hydrates new postings from the detail resource (`job.description`, HTML). An unknown `job_id` answers 200 with no `job.description` and is deferred. The external id is the `job_id` of the row's own `original_apply_url` — which is the requisition id (`P1-6592464-1`) on some sites and the posting token (`PDX_…_<n>`) on others, never the row's own `job_id` field.
- **Date and country only where the site embeds a JobPosting.** `google_json_ld` is a whole `<script>` element as a string; 4 of 6 sampled sites carry it (BurgerKing2, InspireBrands2 do not). Its `datePosted` has a two-digit year (`26-09-23`).
- **A per-IP request budget, refused with 403.** Unpaced at 8 detail workers, one site read ~840 details in under two minutes and was refused the remaining 688; it lifted within minutes. Every request is paced (`paradoxRequestInterval`, ~1.4 req/s), and the first refusal defers the rest of that board's hydration. A first crawl of a 2,000-posting site is therefore ~25 minutes; steady state is the listing pages plus new postings.
- **Not an IT platform.** Restaurant franchisees, retail, care: the catalogue filter judges each title, and nothing sets `IsTechHint`.
