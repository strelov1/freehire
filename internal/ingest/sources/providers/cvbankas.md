**cvbankas traps** (`cvbankas`; live-verified 2026-11-22 from the prod crawl host, plain HTTP, no proxy):

- **robots.txt `User-agent: *` disallows only account and candidate-action routes** (`/issaugoti-skelbimai.html`, `/prisijungti-*`, `/siusti-skelbima-draugui`, `/kandidatuoti-neuzsiregistravus`, `/banner-job-ads/`, the Facebook data-deletion pair). The listing (`/?page=N`) and the posting pages are allowed. The rest of the file blocks named AI crawlers (anthropic-ai, Claude-Web, CCBot, PerplexityBot, ...) with `Disallow: /`; the adapter sends none of those agents.
- **The sitemaps are not usable from the crawl host.** `/sitemap.xml`, `/sitemap_index.xml` and `/sitemap-jobs.xml` all answer Cloudflare's "Attention Required" 403, while `/` and `/?page=N` answer 200 to plain curl. So the adapter walks the listing instead.
- **The listing is the front page, paged, 50 postings a page.** The header says `Rodomi 7 195 skelbimai` (7,195 on 2026-11-22), which is 144 pages; `?page=200` answers a 302. The first page also holds the VIP rows (repeated, deduplicated by id) and the walk ends at the first page with nothing new, with a 400-page ceiling that FAILS the crawl rather than ending it. First page failing fails the crawl; a later page failing ends the walk with the rows gathered. That is not enough for `fullBoardListing`, which this adapter does not claim.
- **A row has no body, so the adapter hydrates new postings only.** A row gives id (`/1-<id>` at the end of the URL), title, employer, place (Lithuanian locative: "Vilniuje"), salary and age. The posting page (~420 KB) carries the body in `<section itemprop="description">`, the employer in the `hiringOrganization` microdata, the nominative place in `jobLocation`/`addressLocality` and the date in `<meta itemprop="datePosted">`. There is no ld+json. An unusable detail response retains the listing identity for retry. A crawl with no usable details or confirmed closures fails. A run reads 1,000 new pages (one a second, two workers); the cold catalogue drains in about seven runs.
- **Salary is read from the row, gross only.** `salary_amount` is `2150-2480`, `Nuo 1800` (from), or a decimal comma (`7,11-9,70`); `salary_period` is `€/mėn.` or `€/val.`; `salary_calculation` says whether the figure is before tax (`Neatskaičius mokesčių`) or after (`Į rankas`). About 40% of rows state net pay; the `Job` cannot mark that, so only gross figures are kept. The posting page spells the digits with U+200C zero-width non-joiners between them, which is why the row, not the page, is the source.
- **Not set: tech hint, work mode, employment type.** The site files postings under its own categories, but nothing on the row or page names one in a structured field the adapter reads, so `IsTechHint` stays false. "Darbas namuose" in a row's place line is not read as remote. Titles are Lithuanian; expect most to resolve no category through `internal/dict/classify` until Lithuanian titles are added (not measured).
