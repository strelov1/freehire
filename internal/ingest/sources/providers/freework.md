**Free-Work traps** (`freework`; live-verified 2026-10-28 from a residential IP and the crawl host):

- **The listing is the site's own public API** (`api.free-work.com/job_postings`, API Platform): 11,642 postings, ~88% in France (GB 916, BE 181, LU 85, CH 67), ~400 created a day, 637 posters, nearly all IT consultancies, ESNs and staffing agencies (Visian, Signe +, CAT-AMANIA, CELAD, Experis, Hays). robots.txt names no AI crawler. No key, no edge: the project User-Agent is served from the crawl host.
- **Every field is slow, so the listing asks for few.** With every field, a page of 50 takes ~15 s to render (the whole board in that shape would outlast a run); with `properties[]` naming only identity, title, employer, place and remote mode, a page of 300 answers in ~4 s, ~40 pages a walk. A nested filter works for the embedded `company` and `location` but not for `job` (an IRI there), so the posting page's family segment comes from the posting resource; the site 301s any family segment to the right one, so a listing-only Job uses a placeholder.
- **The answer's shape follows the Accept header.** `application/ld+json` (a browser, curl's default) gets a hydra collection with `hydra:totalItems` and a `next` link; the crawl client sends `application/json` and gets a BARE list, with no total and no link. The first deploy decoded the hydra shape and failed on its first page (`cannot unmarshal array`). In the bare form, a page past the end is answered with the LAST page again, so the walk ends at a short page or at a page naming no posting it had not already read; `maxPages` fails the crawl rather than ending it.
- **The API refuses every ordering parameter** (`order[...]` answers 400 "non-scalar value"), and the default order is the publication date, which a republished posting moves to the top mid-walk: a walk saw 10 postings twice and missed ~23 of 11,642. Postings are deduplicated by id; any listing page failing fails the crawl.
- **The body is the posting resource** (`/job_postings/<slug>`, ~10-40 KB, ~1 s): `description` plus `candidateProfile`, bought only for postings the catalogue lacks (`HydratingSource`, `CoverageGated` — the listing names the employer), at most 1,500 a run at one request a second, hydration stopping 5 minutes before the deadline. A 404 or a `status` other than `published` is gone.
- **Pay is structured and in the posting's own currency**: `min/maxAnnualSalary` (35% of postings) for employment, `min/maxDailySalary` (49%) for a mission's day rate, `currency` EUR/GBP/USD. A posting with no `currency` (~2%, some with figures) gets no salary. `remoteMode` is `partial` (66%, hybrid), `none` (19%), `full` (1.7%), or null. `experienceLevel` junior / intermediate / senior / expert maps to junior / middle / senior / senior. `contracts` lists every arrangement offered (a mission AND a permanent role is common); only a single one is mapped.
