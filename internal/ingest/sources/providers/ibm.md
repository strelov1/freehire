**IBM traps** (`ibm`; live-verified 2026-10-15):

- **careers.ibm.com cannot be crawled, so the posting pages are never fetched.** It is IBM's Avature tenant, and every path on it — the sitemap and each `JobDetail` page — answers `202` with `x-amzn-waf-action: challenge`, an AWS WAF JavaScript challenge, to a plain client. The un-fronted `ibmglobal.avature.net/en_US/careers/sitemap.xml` answers, but lists 45 utility routes and no postings, so the `avature` adapter cannot serve IBM either. The catalogue comes from IBM's site-search API instead (`POST www-api.ibm.com/search/api/v2`, `appId: careers`, `scopes: [careers2]`) — the same call the ibm.com/careers/search page makes — and its `body` field is the FULL posting text, so the crawl is 25 POSTs and no detail request.
- **`_source` must name every field.** `true` and `["*"]` both return hits with no `_source` at all. The `field_keyword_NN` slots are generic; what each holds is listed beside `ibmSourceFields` in `ibm.go`. `description` is a ~250-char snippet, not the body.
- **The UI's sort ties on every document.** An empty query sorted by `_score, pageviews` returns the same set in a different order on each request, so offset paging would skip and repeat postings. The adapter sorts by `id`, a unique keyword per document. Sorting by `url` or `field_text_01` is a 400 (text fields, no fielddata).
- **`size` tops out at 100** (101 is a 400) and `from` at < 9,990 (a 400 beyond). `hits.total` is exact (`relation: "eq"`) and equalled the distinct job ids read (2,434 of 2,434), which is what earns `fullBoardListing`: any page failing, a non-exact total, or a count that disagrees with the total fails the crawl.
- **The body is flattened and carries a suffix.** Newlines are gone (bullets survive inline as `•`, `·`, `*`, `●`, `▪`, often between no-break spaces), and the posting's own facet values are appended after the text — country, area, work mode, level, city, legal entity, the non-empty ones joined by single spaces. That held for all 2,434 postings; the adapter strips exactly that suffix. About a fifth of the bodies double-encode the right single quote (`â€™`), often next to correct ones, so the whole string cannot be re-decoded; that one sequence was the only mojibake in the catalogue and is the one repaired.
- **The city facet is `"BUDAPEST, HU"` or the placeholder `"Multiple Cities"`**, which names no place — the country alone is used then. The country facet is a NAME, and `"Korea, Republic of"` (17 postings) is one the dictionary does not read, so the country falls back to the city's alpha-2 code. Work mode is `Hybrid`, `Remote` or empty — on-site is never stated, so empty stays unknown.
