**Taiwanese hardware makers** (`mediatek`, `realtek`, `foxconn`, `asus`, `quanta`; live-verified 2026-10-25):

- **Chinese titles carry no category, so the source's own category is what files them.** `internal/dict/classify` reads no Chinese, and a posting with no category and no `is_tech` is excluded from search (`search.CategoryUnresolved`). Each adapter maps its site's category or recruiting track onto `vocab.CategoryValues` where it names ONE discipline, and sets `IsTechHint` for an R&D bucket that spans several (Realtek's 系統設計, ASUS's 研究發展/Data, Foxconn's server and communications R&D tracks). Buckets that span functions (sales-and-marketing, the graduate and campaign tracks) are left unmapped and those postings stay invisible until a dictionary reads them — a deliberate gap, not an oversight. Foxconn has no category field at all, only its recruiting tracks, so most of its catalogue is in that gap. MediaTek titles are English and the dictionary reads them.
- **Place names are Traditional Chinese.** `twplace.go` maps the names these sites state (台灣, 新竹科學園區, 林口研發中心, 萬錦市) to English and a country; `cncity.go` is Simplified and cannot serve them. 臺 and 台 are the same word and are folded.
- **Realtek's listing is capped at 200 rows**, the unfiltered dump included, while the board holds more (279). The search's `xp` filter splits it into two disjoint halves (`xp=0`: no experience asked, `xp=1`: a year or more); a half that returns 200 fails the crawl. An unknown `JobOppId` on the detail endpoint answers 200 with every field null — the not-found signal is a null `JobTitle`.
- **MediaTek's posting page needs the `NEXT_LOCALE=en` cookie.** Without it the locale middleware answers 307 to the same path, and a client without a jar follows it until it gives up. The search API needs no cookie. Underscores in its titles are separators ("2027 Campus_IT Engineer") and are spaced out.
- **ASUS pages five postings at a time and ignores every page-size parameter**, so the listing is ~140 requests. The language is a server-minted session cookie no URL parameter selects, so the crawl reads zh-TW. An unknown `sn` answers 500, so a withdrawn posting reads as a failed detail and is deferred until the listing drops it.
- **Foxconn and Quanta are one response each** (968 and 244 postings), and both servers ignore paging and query parameters. Foxconn's body is split over numbered `desc_N` fields whose use varies per posting (`desc_4` is always the duties); its location is only a country, or 其他 ("other"), which names nothing. Neither claims `fullBoardListing`: a single response states no total to check, and Quanta's once came back with 8 of its 244 vacancies, HTTP 200 and well-formed JSON.
- **Coverage measured on the first live crawl**: MediaTek 621 postings (502 filed by the source category or tech hint, 67 more by the English title dictionary), Realtek 279 (216 + 3), ASUS 688 (406 + 73), Foxconn 917 (241 + 51; 625 unplaced), Quanta 244.
- **Not built**: TSMC's Taiwan catalogue (Avature, `careers.tsmc.com`) sits behind a Cloudflare managed challenge from every host we have; its overseas subsidiaries are already crawled through `successfactors` `ro.careers.tsmc.com`. Delta's own portal listed 13 postings; its SmartRecruiters and iCIMS tenants are already crawled. Synopsys runs TalentBrew in front of Avature: `careers.synopsys.com` listed 698 postings while the `avature` board `synopsys.avature.net` held 668 open, so it is already covered.
