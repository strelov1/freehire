**JustRemote traps** (`justremote`, justremote.co; all verified live 2026-11-17 from a residential IP, plain client, no wall):

- **There is no API, feed or sitemap a plain client can reach.** `/api/v1/jobs` (the path the SPA's bundle names) answers the SPA shell with HTTP 200 to GET and POST alike; `/sitemap.xml`, `/rss`, `/feed` and friends answer the same shell, so a 200 proves nothing — only a body that carries the state document does. The listing is the page itself: `/remote-jobs` embeds `window.__PRELOADED_STATE__ = {...}` and `jobsState.entity.all` holds the open inventory. The adapter decodes it with `json.Decoder`, which stops after the first value, so the trailing `;` and markup need no stripping. A page without the marker FAILS the crawl rather than reading as an empty board (a wall also answers 200).
- **The listing does not paginate.** `?page=2` and every category and country page (`/remote-developer-jobs`, `/remote-jobs-in-poland`, ...) return the byte-identical 84 postings, newest first (ids 28256..29248, 17 Nov back to 18 Oct), each carrying `valid_through` 30 days after posting — so 84 is the whole open inventory, not a first page. Expect ~85 postings in total, ~3 new a day.
- **The listing carries no body and a year-less date ("17 Nov")**; each posting page (`/<category-path>/<slug>`, from the listing's `href`) server-renders a schema.org JobPosting with the full HTML description (JSON string, `<`-escaped) and an exact `datePosted`. `PostedAt` and the body come from there; a failed body keeps the posting list-only and `pipeline.HydrationRetryWindow` re-offers it, and a run that had bodies to read and read none fails (echojobs#2588).
- **~96% of it is a repost of an employer's own ATS posting.** Of the 84, the "apply" link of 81 points at Greenhouse (63), Lever (13) or Ashby (5); only 3 (telusinternational.ai, shyftoff.com, scholars.net) are first-party to this board. That is why the adapter is `CoverageGated` — a covered employer's posting is never stored, so without the gate every run re-fetched ~80 bodies it would discard — and why the source adds little beyond the ~3 non-ATS postings plus coverage of employers whose boards we do not crawl. The mix is mostly non-IT (manager 54, developer 9, customer service 7, marketing 6, devops 5, design 2, writing 1), so `IsTechHint` is NOT set; the title dictionary judges.
- **Everything is "Fully Remote"; where it may be worked from is `location_restrictions`** (83 postings name one country, one names 18, none of the 84 named zero — the empty case is defensive). That list is the `Location` text — a bare "Remote" no longer defaults to global — and a posting naming none gets "Worldwide". `job_type` is `permanent` (80) or `contract` (4); only `contract` is mapped, since `permanent` does not say full-time. Inactive entries (`is_active` false) are dropped.
- **No rate limit was met** over ~120 requests at 2 per second; the adapter fetches with 2 workers, one listing request plus at most one page per unseen, uncovered posting.
