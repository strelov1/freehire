**Cutshort traps** (`cutshort`; live-verified 2026-11-10 against the public syndication XML):

- **One public XML, not a careers-site crawl.** Cutshort publishes a dedicated freehire feed at a fixed S3 URL (`jobs_data_for_freehire.xml` on `cutshort-job-feed-data`). There is no per-tenant board id — the adapter is `boardless` + `aggregator`. The document is the whole inventory Cutshort elects to syndicate (public jobs with hiring intent in the last year), refreshed daily, so `Fetch` is one GET and earns `fullBoardListing`.
- **City expansion duplicates the posting.** Multi-city roles appear once per city under the same `partnerJobId`. Collapse on that id and join the cities with `"; "` — leaving them as separate rows would invent duplicate catalogue identities for one vacancy.
- **Prefer `applyUrl` over `url`.** The apply link carries Cutshort's freehire UTMs (`utm_source=freehire-feed`); the plain `url` does not. Without the UTM the application still lands, but Cutshort cannot attribute the source.
- **Body and facets are inline.** Title, company, HTML description, LinkedIn-style `experienceLevel`, an `experience` floor like `4-7`, structured INR salary bands under `<salaries>`, `workplaceTypes` / `isRemote`, and a country field all sit on the listing row — no detail request. Map only structured fields; the free-text `<salary>` label ("7 - 11 lacs/annum") is redundant with the band.
- **Feed size sits under the shared 64 MiB body cap** (~55 MiB / ~14k rows on 2026-11-10). If the document grows past the cap, `GetXML` fails with `BodyTooLargeError` and the whole provider goes red — there is no pagination escape hatch on this URL. Tell Cutshort before raising the client ceiling.
- **Mostly India, not only tech.** Country defaults to India when stated; otherwise `FallbackCountries=in`. The feed mixes software with design, sales and other roles, so no `IsTechHint`.
